Claude Codeをはじめとする、コーディングAgentによるVibe Codingは開発が早いうえに、可読性を上げるコメントを頻繁に吐き出す。
一方でこの、コーディング段階で吐き出すコメントがあまりにも多く、コード本体がドキュメント化してしまう側面がある。

ここで、以下の問題が発生する
    - トートロジー、自己言及なコメントの多発。`const addNewProducts = () => // 新規商品の追加`
    - ADRやドキュメントへの逆参照、循環参照と情報ソースの多元化。`// 今回のケースではxxxを使用。(ADR-00**)`
    - 上流ドキュメント->下流コードの情報フローの逆流
    - 古い情報ソースの参照
    - 実装タイミングで発生した設計・方針・「Why」の要素がドキュメントに反映されない

ここで、消すべきコメントは
    - 設計・方針・「why」
    - ドキュメントへの参照
    - 履歴・移行の物語
    - テストの意図(describe/it文が語るため)
    - 関数名の言い換え

 一方で、残すべきコメントは以下の通り
    - コード外部の世界における事実（使用する端末やブラウザの使用や想定されるユーザーなどの情報）
    - JSDocなどの署名から読めない「契約」
    - コードブロックの起点

今回作成するSkillsでは、コード実体のドキュメント化を避けるハーネスである。
ADRや設計書などのマクロな判断基準に対して、実装タイミングで起こりうるミクロな判断の書き起こしをperiplus、つまり航海日誌として定義する。
