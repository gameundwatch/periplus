# v0.3.0 — 種別を明示工程にし、濾過を機械化する

## 前提の訂正

判断基準の行き先を `config.json` で切り替える機構は **v0.2.3 で既に動いている**
(`hooks/periplus-activate.js` の `loadConfig`、`skills/pp/SKILL.md` の
「config があれば表より優先」、README の設定節)。当初この版で作ろうとしていたものは
新機能ではなく既存機能の再記述だった。

実際に欠けているのは設定機構そのものではなく、その周りの三つである。

- **設定が効く経路が機械化されていない。** `buildContext` は `criteria` を引数に取り
  ながら本文で一度も使っておらず、README の「hook が criteria を差し込んで注入する」
  は事実ではない。config が効くのは「phase 2 で config を読め」という一行の指示だけで、
  読んだかどうかを検証する手立てが無い。
- **設定の誤りが黙殺される。** 未知のキーは警告なく捨てられ、書いた本人は設定できた
  つもりでいる。
- **種別が記録として残らない。** 種別が書き出されるのは periplus 行きの記述だけで、
  コードと破棄に行った記述の種別はその場で消える。どの種別のコメントが何件書かれて
  いるのかを、誰も数えられない。

この版はこの三つを埋める。

## 決定

### 1. 一つの pre-comment は一つの種別を持つ

複数種別は許さない。`.pre.md` に書き留める時点で、種別が一つに定まる最小単位まで
分割する。分割は再帰的であり、一度割った半分がさらに二つを含むことがある。

ADR 0004 が「分割してから分類する」を定めた続きにあたる。あの決定は分類段階で割る
ことを求めていたが、それでは書き留める段階で既に混ざったものが積まれる。

### 2. phase 1 に足す規則は「1行1件」だけ

```
逆接・並列で二つを繋いだら二行に割る。因果(〜のため)は一件のまま。
```

因果だけが割れないのは、`why` が因果そのものだからである。「タイムアウトが多発した
ため非同期にした」は原因と結果を切り離すと why が消える。逆接・並列は種別の違う二つ
を接続詞で縫っているだけで、縫い目に意味が無い。

時制テスト(過去の状態と現在の性質が同居していたら割る)は**採らない**。捕捉できる
ものが逆接・並列の下位集合であり、注入テキストを二重に膨らませる。運用後に `.all.md`
で history の混入件数を見てから判断する。この実験は `.periplus/.log.md` に引き金付き
で一件置く。

### 3. 種別の集合は閉じる

利用者が独自の種別を追加することはできない。設定できるのは行き先だけである。

種別が MECE であることは、11 項目が互いを排除するよう選ばれていることで成立している。
定義文付きの項目を一つ足せば、その MECE を検証する者は誰もいない。追加したくなる状況
とは、既存のどれにも当てはまらない新しいカテゴリが要るということであり、それは設定
ではなく規律の変更にあたる。

未知のキーと不正な行き先は**警告する**。今の黙殺は、設定したつもりの利用者を既定値の
まま走らせる故障である。

### 4. `history` は改名しない

`legacy` は却下する。あれは「まだ現役だが古いコード」というコードの属性を指す語であり、
種別が分類しているのは記述の主題である。改名すると二方向で誤仕分けが起きる。

- 「以前は同期だった」は経緯だが、そのコードは最新版であって legacy ではない
- 「この分岐は v1 クライアント(legacy)のために残してある」は `current-limits` で
  **コードに残すべき**記述だが、名前の一致で `legacy` に吸われ破棄される

### 5. `criteria` と `kind` を分離する

| 語 | 指すもの |
| --- | --- |
| 判断基準 / criterion | 種別を行き先に対応づける規則。`config.json` が持つのはこれ |
| 種別 / kind | pre-comment 一件が持つ、ちょうど一つの分類 |

`config.json` のキーは `criteria` 据え置き。`to` への改名は行わない — 改名すると既存の
`config.json` が警告なく無効化され、いま直そうとしている沈黙の故障を新たに一つ作る。

`tag` は使わない。複数付く前提の語であり、1 pre-comment = 1 種別 と衝突する。

コマンドは動詞で名乗る。名詞の名前は、それが状態を指すのか操作を指すのかを読み手に
決めさせる。

### 6. 三つのファイルは同じ形を持つ

```
- <作成日時> → <更新日時> `<file>:<line>` [<kind>] <本文>
```

| ファイル | 何が居るか | 行が出ていく契機 |
| --- | --- | --- |
| `.periplus/.pre.md` | まだ配送されていない行 | `/pp-resolve` |
| `.periplus/.log.md` | 種別が periplus を指した行 | pick・昇格・破棄 |
| `.periplus/.all.md` | 一度でも捕獲された全ての行 | 出ていかない |

- 種別が未定の行は `[]`。**濾し残しが機械的に見える**ようになる
- タイムスタンプは二本。更新日時だけが動いて `.log.md` に残っている行は、
  `/pp-discussion` にかけたのに出ていかなかった行であり、最も強い滞留シグナルになる
- **行き先の列は作らない。** 種別と config から常に引けるものを持てば、config を
  変えた瞬間に食い違う第二の情報源になる

`.all.md` は `.periplus/` に置く唯一の archive であり、ADR 0003(periplus は状態で
あって archive ではない)に対する明示的な例外である。これが無い限り、規律が効いている
かどうかを測る方法が存在しない。

### 7. phase 2 を二つのコマンドに割る

```
/pp          = /pp-classify + /pp-resolve   (既定)
/pp-classify = 分割して kind を埋める。書き込みは .pre.md のみ
/pp-resolve  = config を解決して配送し、.pre.md から消す
```

割る線は「判断」と「機械」の間に引く。`/pp-list`(報告)と `/pp-discussion`(実行)が
既に同じ線で割れている。

`/pp-collect` は作らない。収集は hook が常時注入している規則であってコマンドではなく、
その名前をコマンドが持てば「呼ばないと集まらない」と読める。

合成コマンド `/pp` を既定として残すのは、分類だけして放置する経路を既定にしないため
である。commit `0585166` が一度直した故障を、コマンド設計で再発させない。

分類済み未配送(`[kind]` を持ったまま `.pre.md` に残る行)はこの分割が新しく作る状態で
あり、同時に機械的に検出できる状態でもある。session start が未分類と分類済み未配送を
数え分けて報告する。

### 8. 行き先の解決は文章の指示ではなくコマンドが行う

`/pp-resolve` の冒頭で `node .../periplus-activate.js criteria` を実行し、config 適用済み
の種別表を受け取る。`skills/pp/SKILL.md` の表は既定値の記録に降格する。

行き先は JS に書き直さず、出荷された表の行き先の欄だけを差し替える。種別の文言の住所を
一つに保つため。

コマンドに届かなかった場合は既定表にフォールバックし、**フォールバックしたことを黙らない**。
規律が止まるよりは config を無視してでも濾すほうがよいが、設定を無視されたことに気づけ
ない利用者を作ってはならない。

`/pp-classify` はこのコマンドを使わない。種別の定義だけを読み、行き先は見ない。
`history` が破棄されると知っていることは、破棄されないよう別の名前を選ばせる圧力になる。

### 9. ステータスラインは据え置き

`[PERIPLUS:3!2]` の `!2` は `.pre.md` の残数のままにする。内訳は session start が文章で
言う。常時視界に入る二文字の警告に三つ目の数を足せば、警告としての機能が落ちる。

## 書き起こす ADR

昇格の三条件(元に戻しにくい・文脈が無いと意外・実際のトレードオフの結果)を満たすもの。

| 番号 | 主題 | 既存 ADR との関係 |
| --- | --- | --- |
| 0013 | pre-comment は捕獲時点で一つの種別まで分割する | ADR 0006 の「as it came to you / do not decide where it belongs」と競合する。ADR 0004 の続編 |
| 0014 | 種別の集合は閉じる。行き先だけが設定可能で、解決は機械が行う | ADR 0002 の修正。`history`→`legacy` の却下もここに収める |
| 0015 | `.all.md` を `.periplus/` に置く | ADR 0003 に唯一の例外を開ける |
| 0016 | phase 2 を classify / resolve に割り、既定は合成コマンド | 分割自体は先例に沿うが、合成コマンドを残した理由は記録が要る |

ADR にしないもの: 種別と判断基準の分離(→ `CONTEXT.md`)、時制テストの保留
(→ `.periplus/.log.md` に引き金付きで一件)、`config.json` のキー据え置き(→ 0014 の一行)。
