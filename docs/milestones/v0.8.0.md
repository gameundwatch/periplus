# v0.8.0 — 文書が背後にある作業にだけ発火する

いまは引き金が「コードを書くこと」だけなので、単発のモックアップや HTML を一枚書く作業にも発火
する。`/pp` を回す手間が掛かるだけではない。**捕捉した行が指す先は作業が終われば消えるので、
`log.csv` に開けないコードを指す行が残る。**`/pp-discuss` は「最初のエントリが指すコードを開いて
から話す」を最初の一手に置いているので、そこで止まる。

periplus は保守のための機能で、複数のエージェントがコンテクストを跨ぐことを前提にしている。
**保守が要る作品かどうかは、文書が背後にあるかどうかが示す。**文書が無ければ単発であり、濾しても
行き先が無い。

## 決めたこと

**A. 判定するのは作業の出どころである。** リポジトリが文書を持っているかではない。ADR 36 本を持つ
このリポジトリで scratch.html を書く場合、リポジトリで見れば発火してしまう。**リポジトリ単位で切る
のは ADR 0010 が却下した opt-in そのものである。**出どころで見れば、loadmap を根拠に走る実装は発火
し、会話だけを根拠に走る作業は発火しない。

**B. 一文を `hooks/capture.md` の先頭に置く。**

```
None of this applies unless a document stands behind the work.
```

先頭に置くので全体に掛かる。「発火しない作業ではコメントをソースに普通に書く」を別に書かなくてよい
のは、`Nothing is written into the source in this phase` を含むファイル全体がこの一文の下にあるため
である。

**例を書かない。**プラグインは任意のリポジトリに入る。loadmap・ADR・設計文書はこのワークスペースに
在る例にすぎず、並べれば受け取ったエージェントが列挙を必要条件と読む。README しか持たないリポジトリ
で発火しなくなる。

**C. 完了時の報告を三つにする。** `periplus: N filtered` / `periplus: nothing captured` に
`periplus: no document, not run` を足す。`nothing captured` は「走ったが書くことが無かった」であって、
走らせなかったこととは別の状態である。区別が付かなければ hook が死んでいる場合とも区別が付かない。

**D. 迷ったら捕捉する。** 既にある `Still active if you are unsure` をそのまま生かす。単発のつもりが
残った場合、濾されていないコメントがソースに直接入る — periplus が防ごうとしていた失敗そのもので
ある。逆は無駄な `/pp` 一回で済む。復旧路も片側にしか無い(ADR 0017・0008)。

## 変えるもの

- `hooks/capture.md` — 先頭の一文(B)、報告の三つ目(C)
- `docs/adr/0037-*.md` — 新規。却下した案はここが持つ
- `docs/adr/0010-no-activation-condition.md` — 0037 へのリンク一行
- `.claude-plugin/plugin.json` — `0.8.0`

## この版で触らないもの

**コード。** 判定するのはモデルであり、hook は条件を知らない。`SessionStart` はタスクの前に走るので、
作業単位の判定を機構で撃つことはできない(ADR 0010 追記)。

**ADR 0010 の決定本体。** 有効化条件をリポジトリ単位で設けないことは動かない。0037 が足すのは作業
単位の例外である。

**`config.json` の書き出し。** ADR 0027 の決定であり、0010 との食い違いではない。

**テスト。** 変わるのは注入される散文だけで、書けるのは「段落が在るか」型になる。ADR 0036 が却下
している。確認手段は C の三つ目の文言である。
