# pre-comment

コードに書こうとした時点のコメント文。まだ行き先が決まっていないものを指す。

periplus が扱う単位はこれであって、書かれ終えたコメントではない。pre-comment は
code・periplus・drop のいずれかに送られ、送られた先で初めてコメントやログの
エントリになる。文書への経路を持つのは periplus に着いた後であって、この段階では
無い。文書を書くことは合意を要する作業であり、種別から機械的に引ける行き先ではない。

行き先が決まるのは実装中ではなく、コード本体が完成した後である。書いている最中は
判断の根拠が揃っておらず、完成後には不要と分かる記述をその時点では必要に見せる。

記述として浮かんだものが複数の種類を同時に含むことは多い。それは一つの pre-comment
ではなく、まだ割られていない複数の pre-comment である。分割は行き先を決める段階では
なく、書き留める段階で行う。

pre-comment が残ったままタスクが完了することは、コメントが多すぎる状態よりも悪い。
ソースにコメントが一つも入らないことを意味するためである。
