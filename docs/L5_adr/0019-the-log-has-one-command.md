# `/pp-list` を廃し、ログを扱うコマンドを `/pp-discussion` 一つにする

ログ側は報告(`/pp-list`)と実行(`/pp-discussion`)に割れていた。報告を廃し、一つに戻す。

`/pp-list` が持っていた仕事は三つあり、二つは既に他所にある。

- **三つの出口の判定基準** — `/pp-discussion` が同じ基準を持っている。二重管理であり、
  片方だけが直される形をしていた。
- **`no-trigger` の検出** — `/pp-discussion` は引き金の無いエントリを素通しさせない手順を
  持っている。タグを打つより強い。
- **セッション開始時に「新しい作業を始めていいか」を答える** — hook が保留件数と閾値超過を
  毎回出しており、コマンドを打つ理由が無い。

残る一つが `held over` の検出だった。

## `held over` は消えず、読み手が移る

`/pp-discussion` は据え置いたエントリの更新日時を打つ。読み手が `/pp-list` しか居ないなら
このデータは書き込み専用になり、更新日時ごと廃せる — というのが最初の結論だったが、誤り
である。読み手は `/pp-discussion` 自身だった。

一度議論して残ったと知らずにエントリを取り上げれば、前回と同じ議論をもう一度やって、もう
一度据え置く。前回の結論に到達したことすら分からない。次のセッションで再び精査されること
自体は分割とは無関係に起きるが、精査する側がこの事実を必要とする。

そこで更新日時の読みを `/pp-discussion` に移した。併せて、`/pp-list` にしか書かれていな
かった**並び順のキーが created である**ことを `/pp-discussion` に明記した。updated で並べ
ると据え置かれたエントリほど後方に沈み、最も滞留しているものが最後に回る。

## ADR 0016 の線との関係

0016 は phase 2 を判断と機械に割った際、`/pp-list`(報告)と `/pp-discussion`(実行)が同じ線
で既に割れていることを根拠の一つに挙げた。その例が無くなる。

線そのものは `/pp-classify` と `/pp-resolve` では保つ。両者を割る価値は、種別が配送前に
並んだ `.pre.md` を人間が読める瞬間が生まれることにあり、これは実際に存在する。ログ側に
同じ価値は無かった。`/pp-discussion` は元々一件ずつ提案し、一件ずつ同意を取ってから動く。
反対できる場所は実行コマンドの中に既にあり、報告を別コマンドに出しても場所が増えるだけで
機会は増えない。

## Considered Options

- **`/pp-list` を残す** — 読むだけの経路がコマンドとして存在する。ただしログは正常なら
  空に近く、空のログに対する報告は何も言わない。報告が役に立つのはログが不健全なときだけ
  で、そのときに打つべきは `/pp-discussion` である。
- **`/pp-discussion` を廃して `/pp-list` を残す** — 報告だけが残り、出口は手で実行する。
  出口はそれぞれ別の破壊的操作であり、手順を持たないコマンドに落とす意味が無い。
- **更新日時ごと廃する** — 上記の通り誤り。読み手が居る。

## Consequences

ログを扱うコマンドは一つになった。利用者が覚えるコマンドは `/pp` と `/pp-discussion` と
`/pp-refactor` の三つで、`/pp-classify` と `/pp-resolve` は `/pp` の説明の中にだけ現れる。

`/pp-list` が出していた集計(`<N> entries, <M> with no trigger, <H> held over.`)は失われた。
一覧が見たい場合は `.periplus/.log.md` を直接読む。行の形は一定であり、そのために形を
一つにしてある。
