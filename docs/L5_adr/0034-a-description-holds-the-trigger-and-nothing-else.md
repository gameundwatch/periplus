# description は起動条件だけを持つ

ADR 0031 は手順書から理由を落とし、v0.7.0 から v0.7.2 までがそれを実行した。本文は五つの
SKILL.md で 39,292 字から 20,204 字になった。**frontmatter には一度も触れていない。**

description は毎セッション skill 一覧に載る。そのコマンドを一度も呼ばないセッションでも払う。
v0.7.2 の時点で六本の合計は 2,774 字あり、**注入される捕捉規則 1,634 字より大きかった。**
毎セッションの固定費 4,408 字のうち 63% を description が占めていた。

三版かけて呼び出し経路は半分以下になったが、固定費は 5,080 から 4,408 までしか動いていない。
削れていなかったのは frontmatter である。

## 決めたこと

description が決めるのは**この skill が発火するかどうか**だけである。したがって持つのは起動条件
だけとする — いつ呼ぶか、ユーザーがどう言うか。

落とすもの。

- **何をするか** — 本文が持つ。description を読んで発火した後、本文は必ず読まれる
- **内部の手順** — 「`/pp-classify` then `/pp-resolve`」「splitting the rows that hold more
  than one」
- **書き込み先と境界** — 「Writes only `.periplus/pre.csv` — no source file, no log, no ADR」
- **`Invoked as /pp-classify`** — 名前が既に言っている

ADR 0031 の規則をそのまま当てる。**その一文を消したとき、実行結果が変わるか。**description に
とっての実行結果は「正しい時に発火するか」であり、手順の記述はそれを変えない。

## 実測

| skill | 前 | 後 |
| --- | --- | --- |
| `pp` | 844 字 | 348 |
| `pp-refactor` | 587 | 249 |
| `pp-discuss` | 445 | 230 |
| `pp-classify` | 383 | 163 |
| `pp-resolve` | 301 | 171 |
| `pp-capture` | 214 | 149 |
| 計 | **2,774** | **1,310**（−53%） |

毎セッション固定費は 4,408 → 2,944 字。

## Considered Options

- **`pp` の description だけを削る** — 844 字は六本の 30% で、単独で最大である。他の五本は
  一本あたり 200〜590 字で、個別には小さく見える。ただし合計 1,930 字はやはり注入される捕捉規則
  より大きい
- **description を一行に統一する** — 「Periplus phase 2」のような形。固定費は最小になるが、
  `/pp` と `/pp-refactor` と `/pp-discuss` を分ける材料が名前だけになる。三つとも別のものを
  別の時に呼ぶので、名前だけでは足りない
- **`disable-model-invocation` を使って一覧から外す** — 固定費はゼロになる。ADR 0033 が
  `/pp-capture` で却下したのと同じ理由で、`/pp` から呼べなくなる

## Consequences

**description は skill が発火するかを決める唯一の材料である。**削れば発火率が落ちうる。この版が
残したのは、`pp` のユーザー言い回し（"periplus"、"stop commenting everything"、"keep a
logbook"、code turning into documentation）と、各コマンドの呼ばれる場面である。落としたのは
機構の説明だけだが、機構の説明が発火の手がかりになっていた可能性は否定できない。

`/pp-refactor` から `Destructive:` の一行が落ちた。破壊的であることは本文の Boundaries が持って
おり、cut の前に必ず読まれる。ただし description は**呼ぶかどうかを決める段階**で読まれるので、
気軽に呼ばれやすくなる方向には働く。

**発火率を見るテストは無い。**description に対する検査は一つも存在せず、この版は無検査のまま
1,464 字を削った。ADR 0031 が本文について置いた戻し条件（`all.csv` の日次件数）は捕捉の発火率を
見るもので、コマンドの発火率は見ていない。

同じ盲点が三度目である。ADR 0033 は `/pp` が三段を名指ししていることを見るテストが無いと書き、
v0.7.1 の変更はそのために通った。ここでも、削りすぎたことは何かが起きるまで分からない。
