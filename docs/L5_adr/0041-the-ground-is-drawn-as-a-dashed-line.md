# 拠り所は破線で引き、手順を `L6` まで延ばす

ADR 0040 が design を実装の拠り所と定めた。図がその関係を持っていない。

## 参照と拠り所は別の関係である

OVERVIEW の図は矢印を一種類しか持たず、冒頭で「矢印は参照の方向」と定めている。
`adr --> code` は決定が現物を指す関係である。design と code の間にあるのはそれではなく、
**書く者が読む**という関係で、向きも意味も違う。同じ線種には乗らない。

対も現れていない。design は `src` の拠り所であり、contract は `test` の拠り所である。
図の中で `test` はこれまで一度も名指しで指されていない。

## 手順が L1 で終わっている

「新しい話を入れるとき」は「L4 で語と構造を、L3 で約束と構えを、L2 で機能を、L1 で版を書く」
で終わる。出荷の条件も「その話が触れた層の文書が揃い」であり、**コードとテストをいつ書くかを
言っていない。**文書の手順だけがあって、実装の手順が無い。

<a id="two-line-types"></a>
## 決めたこと

- **図に二種類の矢印を持たせる。** 実線は参照、破線は拠り所である
- **破線は二本だけ引く。** `design -.-> code` と `contract -.-> test`
- **手順を `L6` まで延ばす。** 版を書いた後、design を見て code を、contract を見て test を書く
- **出荷の条件に実装を入れる。** `L6` に触れた話は、書けた時点で文書の `_` が外れる

## 層は増やさない

変更を層として立てる案(`L6'`)は採らない。三つ合わない。

- **共消滅の基準に掛からない。** 層は「一つ下の層の要素が消えたときに一緒に消えるか」で分かれる。
  変更は design が消えても消えず、**消えるのではなく `L6` になる**。層の要素は変態しない
- **矢印が逆を向く。** 「上の層のノードからは、下の層のどのノードへ引ける」。`change --> design`
  は下から上への参照であり、層として置くなら `L6` の隣ではなく L1 の上になる。並列にはならない
- **印が既にある。** `_` は「そう書いてあるが、まだそう動かない」を表す。予定と現物の区別は、層で
  はなくファイル名の印で扱うと決まっている

<a id="not-on-the-existing-l6"></a>
**破線は変更のためだけに引かれる。既に動いている `L6` には掛からない。**「`L6` は動かせない」は
そのまま生きる — 現物と文書が食い違ったら、直すのは文書の側である。

## Considered Options

- **変更を層にする(`L6'`)** — 拠り所が層の関係として型を持ち、`change/src --> design` と
  `change/test --> contract` が図に出る。上の三点で合わない
- **拠り所を文だけで書き、図は触らない** — 矢印が一種類のまま保たれる。ただし ADR 0040 が design
  を拠り所と定めた以上、図に無いものを文が言う形になる。design が写しに戻った経路と同じである
- **破線を四本以上引く(structure・adr からも)** — 実装するとき読むのが design と contract だけ
  ではない、という主張は立つ。ただし L3 から下は実線で辿れる。入口を二つに絞るほうが、どこから
  読み始めるかが決まる

## Consequences

**`L6` に入る矢印が二本増える。**これまで `L5 --> L6` の一本が層ごと指していた。code と test が
別々に指されるのは初めてである。

**test が指されるのもこれが初めてである。**`contract -.-> test` が引かれることで、`L3_spec` の
14 枚が誰のための文書かが図に出る。periplus 自身では test が hook の二本にしか無く、散文の側には
無い。その非対称も同じ図で読める。

**`_` を外す条件が二つ並ぶ。**版の `_` は文書が揃ったときに、文書の `_` は実装が届いたときに外れる。
条件が別であることは元から書かれていたが、出荷の条件の側には出ていなかった。
