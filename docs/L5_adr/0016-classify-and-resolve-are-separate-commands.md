# phase 2 を classify と resolve に割り、`/pp` は両方を走らせる合成コマンドとして残す

phase 2 は性質の違う二つの仕事を一息でやっていた。分割して種別を付けること(判断)と、
行き先を引いて配送すること(機械)である。これを二つのコマンドに割った。

```
/pp          = /pp-classify + /pp-resolve   (既定)
/pp-classify = 分割して種別を埋める。書き込みは .pre.md のみ
/pp-resolve  = config を解決して配送し、.pre.md から消す
```

割る線は判断と機械の間に引いた。同じ線で `/pp-list`(報告)と `/pp-discussion`(実行)が
既に割れており、その理由も同じである — 実行される前に、提案に反対できる場所を作る。

分類だけを走らせて止めた `.pre.md` は、種別が並んだ状態で人間が読める。どの記述が
`history` と判定され、どれが `tautology` と判定されたのかを、配送される前に見て直せる
唯一の瞬間になる。

## `/pp-collect` は作らない

収集は hook が SessionStart と SubagentStart で常時注入している規則であって、コマンド
ではない。`/pp-collect` が呼ばれる場面は hook が効いていないときだけで、それは
フォールバックでありフェーズではない。コマンドとして立てれば「呼ばないと集まらない」
と読め、phase 1 が呼ばれなくても効いているという性質を打ち消す。

## 合成コマンドを既定に残す

分割は新しい故障を作る。分類だけして配送しない、という中間状態である。commit `0585166`
が一度直した「`.pre.md` に溜めたまま作業完了とする」が、コマンド設計として戻ってくる。

そこで安全な経路に一番短い名前を与えた。`/pp` を呼べば `.pre.md` は必ず空になる。
halves は、途中を確認したいときに降りていくものとして残す。

**この節が消えると故障が戻る。** 二つのコマンドがあるなら `/pp` は冗長に見え、善意で
削除されうる。それがこの決定を ADR にした理由である。

中間状態そのものは機械的に検出できるようにした。種別の欄が空の行は分類前、種別を持った
まま `.pre.md` に残っている行は分類済み未配送であり、session start が両者を数え分けて
報告する。これまでの「未濾過 N 件」はどこまで進んだか分からなかったが、以後は続きが
`/pp-resolve` だけだと分かる。

## Considered Options

- **収集と分類で割る**(`/pp-collect` + `/pp-resolve`) — 最初に検討した線。収集がコマンド
  ではないという理由で却下した。加えて、配送が二つのうちどちらの仕事なのかが定まらない。
- **割らない** — 中間状態が存在しないので、新しい故障も生まれない。ただし種別を配送前に
  見る機会も無く、`/pp-refactor` が分類の手順を自前で持ち続ける。
- **`/pp` を廃して halves だけにする** — 名前の対称性は最も良い。既定が安全でなくなる。

## Consequences

コマンドは三つに増えた。利用者が覚えるべきものは `/pp` 一つのままで、残る二つは
`/pp` の説明の中にだけ現れる。

ステータスラインは据え置いた。`[PERIPLUS:3!2]` の `!2` は `.pre.md` の残数のままで、
未分類と未配送の内訳は session start が文章で言う。常時視界に入る二文字の警告に三つ目
の数を足せば、警告としての機能が落ちる。
