# 設計は L4 だけを見て書き、決定を見ない

`L3_design` の 4 枚が ADR の言い換えになっていた。

## 参照は閉じていた。それでも写しが起きた

`L3_design` は `## Decisions` の節を持たず、L5 へのリンクは 0 本である。**参照上は最初から
閉じていて、内容だけが写された。**

- `L3_design/state.md:18` と `L3_spec/pp-resolve.md:19` は同じ文で、design 側だけが末尾に
  「〜ので」を足している
- `L3_design/commands.md` の「分類は行き先を見ない」は、ADR 0027 が `/pp-classify` への命令
  として引用した内容と同じである
- `L3_design/phases.md` の「命令に理由を添えると反論の足場ができ、規律が弱くなる」は
  ADR 0031 の主張そのものである

`L4_structures` は 11 枚すべてが図か EBNF を持ち、`L3_design` は 4 枚とも文だけである。
**文だけで書かれた「なぜこうなっているか」は、ADR と見分けがつかない。**

## ADR を合成しても design にはならない

OVERVIEW の二つの規則が正反対を命じている。撤回の印は「文は消さない。当時そう決めたことは
記録として真であり続ける」と言い、`L6` は動かせないは「文書と実装が食い違ったなら、直すのは
文書の側になる」と言う。**ADR は古い決定を保存する義務を負い、design は古い記述を消す義務を
負う。**

義務が逆であるうえ、ADR は一枚が一つの論点しか見ていない部分解である。実装者が手を止めるのは
論点の間であり、そこはどの ADR も担当していない。

<a id="closed-on-l4"></a>
## 決めたこと

- **design は `L4` だけを見て書く。** ADR を出発点にしない
- **書けるのは、L4 の図と語だけで言い切れることに限る**
- **一枚の L4 で足りる文は、その L4 に返す。** design に残るのは図を二枚以上またぐ文だけである
- **言い切れない文が出たら二択。** L4 に構造が足りないなら L4 に足し、取引だったなら ADR に返す
- **照合は書いた後に行う。** 矛盾したときは、design ではなく ADR の読み違いのほうから疑う

閉じることの担保を、参照先ではなく**書ける内容**に置いた。リンクを 0 本に保っても写しは防げない。

## ADR 0016 と同型である

0016 は `/pp-classify` に `config.json` を読ませない。「行き先を知っていると、行き先の都合で
kind が選ばれる」からである。同じことが一段上で起きていた。**決定を知っていると、決定の都合で
設計が書かれる。**

## Considered Options

- **現状維持** — L5 へのリンクが 0 本である以上、参照グラフの上では違反が無い。実測で写しが
  三箇所見つかっており、検出できないことがこの選択肢の問題である
- **design に `## Decisions` を許し、写した先を明示する** — 写しが追跡可能になる。ただし
  ADR 0031 は「詳細は ADR 0029 と書けば根拠は辿れる」案を、参照が `doc-restatement` の定義
  そのものだという理由で却下している。同じ形になる
- **design を廃し、L4 と ADR に返す** — 層が一つ減る。図を二枚以上またぐ文の置き場が消え、
  実装者は 11 枚を自分で突き合わせることになる
- **ADR から実装規則を引き上げて design にする** — 一見すると出所が一つになる。ADR を出発点に
  する形そのものであり、写しの向きが変わるだけである

## Consequences

**4 枚は空にしてから書き直す。**残したまま書けば、L4 ではなく既存の文 — すなわち写し — を
見ることになる。

**ファイル名は据え置く。**`L2_features` と `L3_spec` から 26 本のリンクが名前で張られている。
またぎ方の名前として `commands` `failure` `phases` `state` が妥当かどうかは、書いてみるまで
判定できない。

**「なぜ」で指している 4 箇所のリンク説明が偽になる。**`L2_features/filter.md:23`「なぜ二つに
割れているか」、`L2_features/capture.md:22`「なぜ判断を後段に集めるか」、
`L2_features/discuss.md:17`「なぜ合意の要る操作だけ別のコマンドなのか」、
`L3_spec/pp-classify.md:29`「分類が行き先を見ない理由」。**features と spec が design に理由を
発注していた**のがこの四行であり、この版で書き換える。

**design は薄くなる。**一枚の L4 で足りる文が返るため、残るのは横断する文だけになる。薄いこと
自体は不足の印ではない。

**L4 の穴が露出する。**L4 だけを見て書こうとして書けない文が出たとき、それは L4 に図が足りない
という報告になる。この版はその報告までを行い、L4 への追加は行わない。
