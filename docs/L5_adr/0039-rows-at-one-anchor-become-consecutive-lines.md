# 同じ位置に届く行は連続した行に書き、配送は後ろから前へ

`/pp-classify` は分割した行を**同じ `file:line`** に置き換える(`skills/pp-classify/SKILL.md`)。
`/pp-resolve` は「行の `file:line` に書け」としか言っていない。**一行に二つのコメントは
置けないので、両方が `code` に行くと書き手が繋ぐ。**分割で割ったものが配送で戻る。

再結合はモデルの気まぐれではない。**指示がそれ以外の書き方を与えていない。**

独立した故障がもう一つある。一行挿入すると以降の行番号が全てずれる。`/pp-resolve` は
一行ずつ配送すると決めているので、二件目以降は古い位置を指す。

<a id="consecutive"></a>
## 同じ位置に届いた行は、連続した行として書く

繋がない。二行として書く。一行一記述は分割が保証したものであり、配送がそれを崩す理由は
無い。コメントが二行以上になることは受け入れる。

<a id="descending"></a>
## 配送は行番号の大きいものから小さいものへ

挿入が以降の位置をずらさないので、行番号を数え直さずに済む。並べ替えるのは配送の順序で
あって、分類の順序でも保管の順序でもない。保管と `pre.csv` の排出は今まで通り一行ずつで、
順序だけが変わる。

## Considered Options

- **繋ぐ** — 現状。一行に収まるが、分割した意味が消える。長い一行コメントが生まれる
- **両方 `code` のとき利用者に問う** — ADR 0012 の「文言で頼む」に沿う。ただし
  `/pp-resolve` は「機械的に解決するので確認を求めない」と決めてあり、性格が変わる
- **`/pp-classify` が分割時に行番号を振り分ける** — 記述は一箇所から生まれたので、
  割った先の行番号を分類の段では知りようがない
- **配送のたびに行番号を数え直す** — 正しいが、`/pp-resolve` に位置の追跡を持たせる。
  後ろから配れば追跡は要らない

## Consequences

一箇所に二行以上のコメントが並ぶことがある。分割が細かいほど増える。`1 line - 1 comment`
は守られるので、読み手には一行ずつ別の事実として読める。

`/pp-resolve` は配送の前に行を並べ替える。並べ替えは出力の報告順にも現れるため、
報告が捕獲順ではなくなる。
