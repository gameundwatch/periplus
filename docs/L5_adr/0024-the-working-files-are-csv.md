# 作業ファイルは CSV であり、markdown ではない

`.periplus/` の4ファイルが持っているのは散文ではなく**5列の表**である。1行1レコードで、
列は固定で、見出しも段落も箇条書きも現れない。markdown である理由は最初から無く、
拡張子だけがそう名乗っていた。

**拡張子は無害ではなかった。**この決定を書いている時点の `.periplus/.log.md` は `# log`、
`.all.md` は `# all` で始まっている。どの skill もヘッダを書けとは指示していない。`.md` が
書き手にそう振る舞わせた、というのがこの二行の意味である。規律が「書式の行はこれ一つ」と
言っている場所で、名前が別のことを言っていた。

## なぜ CSV か

候補は行指向の三つだった。**JSON 配列は最初に落ちる** — phase 1 の書き込みは思いついた
瞬間の1行 append であり、配列は末尾の `]` を毎回書き換える読み書きを要求する。append
専用であることは、archive が「編集されず、決して drain されない」(ADR 0015 / 0018)ことと
同じ性質に属する。

残る三つを分けたのは body のエスケープである。body は自由文で、`、` と `,` は高頻度、
ASCII の `"` も入りうる。

- **JSONL** — エスケープ規則は完全に規格化されており、機械可読性では最も強い。ただしキー名
  で1行あたり約40文字を払い、読み書きの文字数は現行の markdown より**増える**。この決定が
  下げようとしているものの一つを上げる
- **TSV** — body にタブは入らないのでクオート規則が一切不要になり、最短。区切りが目に見えない
  ことが代償で、`/pp-discuss` は行を人に見せるコマンドであり、手で直される場所でもある
- **CSV** — 素直に書くと「この行の body にカンマが有るか」を毎行判断させる。判断を増やすことは
  書き損じを減らすという目的に逆行する

CSV を採り、判断のほうを消した。**body を最後の列に固定し、中身に関わらず常にクオートする。**
条件が消えて規則だけが残り、RFC 4180 準拠のまま表計算とスクリプトがそのまま読める。

## 行内スキーマ

```
<timestamp>,<file>,<line>,<kind>,"<the note>"
```

| 列 | 規則 |
| --- | --- |
| `timestamp` | ISO 8601 分まで。捕獲時刻であり、以後動かない |
| `file` | パス |
| `line` | 数値。不明なら空欄 |
| `kind` | 閉じた12種。未分類は空欄 — 旧書式の `[]` にあたる |
| `body` | 常に `"` で囲み、中の `"` は `""`。改行を含まない |

**列順が「body 末尾」を含んでいる。**提案の時点では `timestamp,file,line,body,kind` だったが、
body が最後でなければ「常にクオート」は成立しない。これは並べ方の好みではなく、上の判断を
消す仕組みそのものである。

**body に改行を入れない規則は、CSV が新しく持ち込んだ危険への蓋である。**markdown の行書式では
改行は物理的に不可能だった。CSV ではクオート内の改行は合法で、準拠パーサは正しく1レコードと
して読む。一方で件数を数える側はファイルを行で割る。body に改行が一つ入れば件数が黙って
ずれる。実際に起きうる経路は `/pp-refactor` で、複数行のブロックコメントを素直に切り出した
ときである。「一行一件」(ADR 0013)と同じことを言っているので、規律に新しい軸は増えない。

## ヘッダを置かない

`pre.csv` は最初の1件で作られるファイルである。ヘッダを置けば、毎セッション注入される capture
rule に「無ければヘッダを先に書く」という条件分岐が一つ増える。減らそうとしている書き損じの
余地が、そこに戻ってくる。append する側は `/pp-resolve` と `/pp-refactor` にもある。

ヘッダはスキーマの二つ目の記述でもある。criteria 表を SKILL.md から実行時に読ませているのと
同じ理由で、独立して古くなれる複製を増やさない。

**後から足すことは壊れない。**行を数える正規表現は先頭フィールドが ISO 日時であることを要求
するので、ヘッダ行はレコードとして数えられない。この決定は「今は置かない」であって、置けなく
することではない。

## 名前から先頭のドットを落とす

`pre.csv` / `log.csv` / `all.csv` / `swept.csv`。`.periplus/` 自体が既に隠しディレクトリであり、
その中で二重に隠す意味は無い。同じディレクトリの `config.json` はもともとドットを持たず、
現状は不揃いだった。拡張子を変える置換で同時に済む。

## 移行措置を立てない

ADR 0023 が `updated` を落としたときと同じ扱いにする。旧 `.md` は放置され、新しい `.csv` が
隣に作られる。`.periplus/` は untracked で(ADR 0009)、影響はファイルを持っている個人の手元に
閉じる。

前回より代償は大きい。ファイル名ごと変わるため、旧ファイルは行が数えられないだけでなく**誰も
読まない孤児として残る**。ログの滞在は 0023 以降「文書を書くときの客観的証拠」であり、それが
黙って見えなくなる。それでも自動変換を持たないのは、利用者の記録を合意なしに書き換えるコード
を規律の側に置かないためである — `/pp-discuss` がエントリ一件ずつに同意を要求しているのと
同じ線を引く。

## 書式の複製は各 skill に残す

書式の記述は `pp/SKILL.md` に2箇所、`pp-classify` / `pp-resolve` / `pp-refactor` と `README` に
1箇所ずつある。一本化しない。

**最も重要な複製は既に単一ソースである。** capture rule の書式行は always 領域の中にあり、hook
が実行時に SKILL.md から読んで注入し、一致はテストが保証している。書式を間違えると黙って壊れる
唯一の経路は、既に一箇所から来ている。

残る複製はそれぞれ別のコマンドに属し、**別のファイルを読む**(`pre` / `log` / `swept`)。skill は
単体で呼ばれるので、書式が目の前に無ければ別ファイルを開くか、開かずに推測する。後者の失敗は
黙って起きる。複製が古くなる失敗は、読めば分かる。使用地点に書式を残すほうが安い。

代わりに**ズレをテストで壊す**。`skills/*.md` と `README.md` の書式テンプレート行を拾い、
プレースホルダを実値に置いた行が `ROW_RE` にマッチすることを確認する。skill だけ直して正規表現
を直し忘れた場合も、その逆も落ちる。

## Considered Options

- **`.pre` と `.log` だけ CSV にする** — 提案の字面通り。コードが読むのはこの二つだけなので変更は
  最小になる。archive が別形式で取り残され、「一つの形だから、どのファイルに居るかが進捗を表す」
  という設計の根拠を失う。集計の器である archive(ADR 0015 / 0022)が最も読みにくいファイルになり、
  機械可読性という目的自体と矛盾する。
- **ヘッダを置く** — 表計算とスクリプトが列名をそのまま拾える。捕獲時の条件分岐とスキーマの二重
  記述を代償にする。列は5つで固定であり、読む側の1引数で済む。
- **body の改行を許し、数える側を CSV パーサにする** — 形式としては正しい。依存無しでクオートを
  追う実装を hook が抱えることになり、「一行一件」に反する行が正当になる。
- **書式を `pp/SKILL.md` に一本化する** — 編集箇所が一つになる。書式を使用地点から引き剥がす。

## Consequences

行の読み書きは、区切りの数え違いか、クオートの閉じ忘れか、改行の混入でしか壊れなくなる。
どれもバッククォートと角括弧の書き損じより見つけやすいが、**黙って壊れる性質は変わらない** —
壊れた行は例外を出さず、単に数えられない。

capture rule が1行ほど伸びる。テンプレート行がクオートを可視で含むので大半は例示で済むが、
`""` の二重化は語で要る。always 領域を縮めたいという要求とは逆方向に効く。

`.log.csv` は人に見せるファイルでもある。`/pp-discuss` が行をそのまま出したとき、読めるが、
markdown の行より装飾が少ない分そっけない。

拡張子が `.csv` になったことで、書き手が markdown 的な装飾を足す余地は消える。`# log` が
再び現れることは無い。
