# 掃除が刈ったコメントは `.swept.md` に落とし、`.all.md` と混ぜない

ADR 0015 は「`.pre.md` に入った行は全て `.all.md` を通る」と決め、`/pp-refactor` が
集めた既存コメントもそこに入ると書いた。その上で consequence に、掃除を走らせれば種別の
分布が動くという注意書きを残した。

ADR 0017 で掃除が切り取りになったことで、注意書きでは足りなくなった。掃除は範囲内の
コメントを全部刈るため、コメントが数百個あるコードベースで一度走らせれば、`.all.md` は
他人が書いた行で埋まる。`.all.md` が答えるべき問い(この規律の下でどの種別が何件書かれて
いるか)に、そのファイルはもう答えられない。

より重い理由がある。**periplus を通したコードを後から掃除した場合**、刈られたコメントが
`.all.md` に入れば、それが `/pp` の配送したものなのか新しく捕獲したものなのか区別が
つかない。`/pp` が機能不全を起こしているかどうかを、そのファイルからは判断できなくなる。

分けておけば逆に診断になる。`/pp` が code に配送したコメントが、後の掃除で `tautology` と
判定されたなら、それはフィルタが素通しした証拠として読める。二つのファイルが分かれて
いて初めて成立する読み方である。

副次的に `.swept.md` は対照群になる。規律の下で書かれたコメントと、規律の無い場所で
書かれたコメントを並べれば、tautology と history の比率が実際に違うのかを比較できる。

## 不変条件の書き直し

ADR 0015 の「`.pre.md` に入った行は必ず `.all.md` を通る」は、「**`.pre.md` を出た行は
必ず archive に着く**」に置き換わる。archive は二つあり、どちらに着くかは行の出自で
決まる。

これは三つのファイルで採った考え方(どのファイルに居るかがその行の状態を言う)と同型で
ある。行に出自の列を足す案は採らない — ADR 0015 が行き先の列を作らなかったのと同じ
理由で、行に持たせれば重くなり、ファイルの違いで足りるものをもう一度書くことになる。

書式は四つとも同型のままなので、`ROW_RE` も読み書きの手順も変わらない。

## Considered Options

- **ADR 0015 のまま混ぜ、注意書きで運用する** — ファイルは増えない。ただし上の二つの
  問題がそのまま残り、特に二番目(自分の機能不全が見えない)は運用では回避できない。
- **掃除の分は archive に書かない** — 母集団は汚れない。ただし「`.pre.md` を出た行は
  必ず archive に着く」が破れ、切り取ったコメントの行方が追えなくなる。掃除が破壊的に
  なった版でこれを外すのは方向が逆である。

## Consequences

`.periplus/` のファイルは四つになった。うち二つが archive で、どちらも出ていかない。

hook はこのファイルを数えない。session start が報告するのは日誌と `.pre.md` の状態だけで
あり、archive は規律の実行には関与しない。
