# サブエージェントには規律だけを渡し、親の未処理は渡さない

`SessionStart` と `SubagentStart` は同じ hook を叩くが、渡すものは同じではない。親の
セッションは未配送の警告 — `pre.csv` に残っている件数と、その内訳(未分類 / 分類済み未配送) —
を受け取る。**サブエージェントは受け取らない。**規律の本文だけが渡る。

その行を書いたのは親である。サブエージェントが警告を受け取れば、規律に従って `/pp` を走らせ、
親の `pre.csv` を drain する。**それは誰も合意していない配送になる。**委譲した側は分類も行き先も
見ないまま、ソースにコメントが書かれ、`log.csv` に行が積まれた状態を受け取る。ADR 0016 が
`/pp-classify` と `/pp-resolve` を割った理由 — 実行される前に提案へ反対できる場所を作る —
が、委譲の境界で失われる。

未配送の報告は、その行を書いた側にだけ届く。

## Considered Options

- **親と同じものを渡す** — 分岐が一つになり、`buildContext` の引数も減る。サブエージェントが
  親の `pre.csv` を drain しにいく。差分が消えることと引き換えに、合意なき配送が入る。
- **件数だけ渡し、指示を付けない** — 数は見えるが行動は促さない。ただし未配送の件数は規律の
  他の場所で常に「`/pp` を走らせろ」と対で出ており、数だけ見せて何もするなという状態は、
  同じ数字に二つの意味を持たせることになる。
- **サブエージェントへの注入自体をやめる** — ADR 0007 が既に却下している。委譲先で規律が切れる。

## Consequences

サブエージェントは親の未配送に気づけない。委譲先で作業が終わり、親が `/pp` を忘れた場合、
**警告を誰も見ない経路が残る。**これは ADR 0006 が挙げた「ソースにコメントが一つも入らない」
失敗そのものであり、対策(件数報告)が届かない一点を意図して開けている。

分岐が二つあることは、揃えにいく修正を招く。`buildContext` が既定引数を持ち、片方の呼び出しが
それを使っていない形は、片方が古いようにも読める。**この節が消えると、その修正が正しく見える。**
それがこの決定を ADR にした理由である。

nudge も同じ分岐にあるが、根拠は別で、コードの傍に残る — サブエージェントにステータスラインは
無い。規律の設計ではなく実行環境の事実であり、ADR に持ち上げるものではない。
