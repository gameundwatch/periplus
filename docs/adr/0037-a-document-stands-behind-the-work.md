# 文書が背後にある作業にだけ発火する

ADR 0010 は有効化条件を設けないと決めた。**その決定は動かない。**足すのは作業単位の例外である。

periplus は保守のための機能で、複数のエージェントがコンテクストを跨ぐことを前提にしている。単発の
モックアップにはその前提が無い。**捕捉した行が指す先は作業が終われば消えるので、`log.csv` に開け
ないコードを指す行が残る。**`/pp-discuss` は最初のエントリが指すコードを開くところから始まるので、
そこで止まる。

## 決めたこと

`hooks/capture.md` の先頭に一文を置く。

```
None of this applies unless a document stands behind the work.
```

先頭に置くので全体に掛かる。判定するのは**作業の出どころ**であって、リポジトリが文書を持っているか
ではない。完了時の報告に `periplus: no document, not run` を足す。迷った場合は捕捉する — 既にある
`Still active if you are unsure` がそのまま効く。

## Considered Options

- **リポジトリが文書を持っているかで見る** — hook で決定的に撃てる。ただし ADR 0010 が却下した
  「`.periplus/` の存在を opt-in シグナルにする」と同じ形であり、0010 の反転になる。ADR を 36 本
  持つこのリポジトリで `scratch.html` を書く場合も発火するので、痛みが消えない
- **書こうとしているファイルを名指しする文書があるかで見る** — ファイル単位で決まる。ただし文書に
  ファイル名が載るのは実装の後なので、**新規ファイルは必ず取りこぼす**
- **行き先が `trash` しか無いかで見る** — 適用対象の性質そのものを言える。ただし走らせないと分から
  ないので、起動条件にはできない
- **配送側で `file` が存在しない行を落とす** — 有効化条件を一切足さずに `log.csv` の腐りを消せる。
  ただし消されずに残ったモックアップには撃たず、捕捉と `/pp` の手間も残る
- **迷ったら捕捉しない** — 過剰捕捉が消える。ただし非対称である。単発のつもりが残れば濾されていない
  コメントがソースに直接入り、それは periplus が防ぐはずの失敗そのもの。逆は無駄な `/pp` 一回で
  済む。復旧路も片側にしか無い(ADR 0017・0008)
- **例を並べる(loadmap・ADR・設計文書)** — `document` の曖昧さが減る。ただしプラグインは任意の
  リポジトリに入るので、**列挙が必要条件として読まれる**。README しか持たないリポジトリで発火
  しなくなる

## Consequences

判定はモデルが行い、機構の保証は無い。`SessionStart` はタスクの前に走るので、作業単位の条件を hook
で撃つことはできない(ADR 0010 追記)。ADR 0007 追記が「機構による保証から指示による依頼へ」と書いた
のと同じ形である。

発火しない作業では、コメントは普通にソースへ入る。濾す工程が無いだけで、periplus を入れる前の挙動に
戻る。

注入は 10 語増える。

テストは足さない。変わるのは注入される散文だけで、書けるのは段落の存在を見る型になる(ADR 0036)。
確認手段は完了時の三つ目の文言である — 文書の無い作業で `no document, not run` が出て、loadmap を
根拠に走る作業で `N filtered` が出れば、判定は使えば分かる。

**捕捉しすぎる場合は後続の版で直す。**この版は迷いを捕捉側に倒しており、倒しすぎたかどうかは実際に
溜まった量でしか分からない。
