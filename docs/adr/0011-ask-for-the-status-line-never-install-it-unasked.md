# ステータスラインは依頼して入れてもらい、勝手に入れない

`.periplus/` は隠しディレクトリなので、ログの保留件数と未フィルタの pre-comment 件数は
外から見えない。ステータスラインの `[PERIPLUS:3!2]` はその2つを常に見せる唯一の場所で、
規律が生きているのか単に何も捕捉されていないのかを、セッション開始時の一行を待たずに
区別できるようにする。

ところがプラグインは自分でこれを入れられない。プラグイン自身の settings.json から読まれる
のは `agent` と `subagentStatusLine` だけで、`statusLine` は読まれないため、配布物に同梱
するという最も素直な方法が成立しない。残る手段はユーザの `~/.claude/settings.json` を書く
ことだが、それは hook が勝手にやることではない。よって **hook は依頼し、書き込みは
`install` サブコマンドをユーザが明示的に叩いたときにだけ起きる**。

依頼は `statuslineNudge()` が返す一行で、既に配線済みなら何も言わない。判定は statusLine
の有無ではなくコマンド文字列に `periplus-statusline` が含まれるかで行う — このプラグインの
利用者はたいてい別のステータスラインを既に持っているため、有無で判定すると毎回配線済みと
誤認する。

## Considered Options

- **プラグイン自身の settings.json で配布** — 不可能。`agent` と `subagentStatusLine` しか
  読まれない。Claude Code がプラグインの settings.json から `statusLine` を読むようになった
  時点で、この ADR の前提が消えるので nudge ごと削除できる。
- **hook がセッション開始時に `~/.claude/settings.json` を直接書く** — 却下。プラグインが
  ユーザのグローバル設定を無断で編集するのはすべきことでない。nudge が毎セッション無視され
  続けると報告されたときのみ再検討する。
- **`install` を独立スクリプトか `/pp-statusline` スキルにする** — 却下。nudge は
  `__filename` をそのままコマンドに引けるので、hook と同居していればパスが必ず存在する。
  独立スクリプトでは nudge が別パスを組み立てることになり、スキルは結局同じスクリプトを
  叩くだけになる。他にインストールすべきものが出てきた時点で、独立スクリプトが場所を得る。

## Consequences

`install` はユーザのグローバル設定を書き換えるので、既にあるステータスラインは
`; printf ' '; ` で連結して後ろに periplus を置き、書き込み前に `.periplus-bak` を残す。
periplus が最後なのは、ステータスライン JSON を stdin から読んでプロジェクトディレクトリを
取るのが periplus だけで、stdin を無視するコマンドが前にいると読み取れなくなるため。整形と
キー順はラウンドトリップで失われる。

コマンドはキャッシュを glob で引く。キャッシュはバージョン付きなので、このリリースに固定した
パスは次の更新で解決しなくなり、配線済み判定はそれを配線済みと報告し続ける。

nudge は hook が出す文字列にすぎず、ユーザに届くかはモデルが伝えるかどうかに依存する。
Windows では `STATUSLINE_CMD` の glob が POSIX 専用で叩けないため、nudge は手動の手順を
案内する形に落ちる。
