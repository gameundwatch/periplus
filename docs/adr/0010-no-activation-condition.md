# 規律に有効化条件を持たせない — hook が `.periplus/` を作る

ADR 0001 は「hook はインストールした全プロジェクトで発火するため、periplus を使わない
リポでの挙動を別途決める必要がある(規律の有効化条件)」を宿題として残していた。`.periplus/`
の存在をその条件に使えば opt-in 方式が成立するが、それは採らない。

ponytail と同じく、**コードを書く動作そのものが引き金**である。コメントを書きたくなる
瞬間はリポジトリの設定と無関係に訪れるのだから、そこに opt-in を挟むと、規律を最も必要
とする「まだ periplus を入れていないリポジトリ」でだけ規律が効かない。よって有効化条件は
設けず、hook はセッション開始時に `.periplus/` が無ければ作り、`.gitignore` に追記する。

生成をセッション開始時に行う理由は gitignore の自動化ではなく、**観測可能性**にある。
遅延生成では、最初の pre-comment が書かれるまで `.periplus/` は存在しない。つまり規律が
効いているのか、単に何も捕捉されていないだけなのか、hook が動いていないのかを外から
区別できない。空のディレクトリが在ることが、規律が生きている唯一の可視な証拠になる。

`config.json` は hook では書き出さない。既定値をファイルとして固定すると、プラグイン側の
既定が更新されたときにリポジトリが古いスナップショットを持ち続けることになる。設定を
置いていないリポジトリは常に出荷時の既定に追随する。

## Considered Options

- **`.periplus/` の存在を opt-in シグナルにする** — 使わないリポジトリで hook が完全に
  沈黙する。ただし規律は「日誌を持つリポでのみ効くもの」に変質し、常時オンという前提が
  崩れる。
- **遅延生成のまま指示だけで賄う** — ファイルシステムに一切触れずに済む。ただし生成も
  `.gitignore` の追記もモデルの遵守に依存し、決定的に書ける処理を確率的な指示に任せる
  ことになる。上記の観測可能性も得られない。

## Consequences

hook はセッション開始時にユーザのリポジトリへ書き込む。コードを一切書かずに開いただけの
リポジトリにも `.periplus/` と `.gitignore` の2行が残り、これは periplus が持つ唯一の
無条件な副作用である。書き込みは初回のみで、`.gitignore` の行を手で消した場合は書き戻さ
ない。読み取り専用のチェックアウトでは生成に失敗するが、規律の注入自体は続行する。

## 追記 (2026-08-13)

**「コードを書く動作そのものが引き金である」は意図であって、機構ではない。**実装は
`SessionStart` と `SubagentStart` の注入であり、規則が常時コンテキストにあることで引き金を
近似している。編集そのものを検知する機構は使っていない。この ADR は両者を書き分けていな
かった。

検知自体はできる。CLI 2.1.228 は `PreToolUse` / `PostToolUse` を持ち、`matcher` にツール名を
書けばファイル編集で発火する。それでも注入を置き換えられない理由は**順序**にある。どちらの
イベントも、モデルが編集内容を組み立てた後に発火する。規則は組み立てる前にコンテキストへ
無ければ効かず、イベントで撃つ限り常に一編集ぶん遅れる。既にソースへ入ったコメントを剥がす
工程が要ることになり、ADR 0008 が却下した掃除に戻る。

したがって引き金の記述はこう読む。**引き金はコードを書く動作であり、それを保証する機構は
常時オンの注入である。**編集イベントで撃てるのは規則ではなく合図 — `pre.csv` の件数、`/pp`
をまだ呼んでいないこと — に限られる。有効化条件を設けないという決定そのものは動かない。

## 追記 (2026-08-18)

作業単位の例外を [ADR 0037](0037-a-document-stands-behind-the-work.md) が足した。リポジトリ単位で
有効化条件を設けないという上記の決定は動かない。
