# `.log.md` は文書を書くための証拠であり、出口を要求しない

ADR 0022 が `unspecified-choices` を足したことで、periplus に着く既定の種別は二つから三つに
なった。新しい一つは「後でやること」ではなく**まだ決まっていないこと**であり、ログに滞在する
記述の性質が変わった。0022 の Consequences はこの書き直しを v0.3.6 に送っている。

**`.log.md` はログである。**文書にエスカレーションされない記述は残るべくして残る。滞在は
処理されていない在庫ではなく、**いずれ文書を書くときの客観的証拠**の蓄積である。

periplus を分けるのは処理の進捗ではなく**決着の有無**である。決着した記述は code・docs・
trash のいずれかで出ていき、決着していない記述は留まる。

## 出口を要求しない

`here` に行き先を決めさせると、次はその行き先のファイルを議論するコマンドが要り、その先も
要る。連鎖は終わらない。エントリごとに「出ていく条件」を書かせる規則は、この連鎖の一段目を
強制しているだけであって、規律を締めてはいない。

決着していない記述が文書の試験を通らないのは、失敗ではなく試験が働いているということである。
通してしまえば、未決の問いが決定として記録に入る。留まっていること自体が、その決定がまだ
誰かに負われていることの記録になる。

ログが伸びることは、設計が決めずに実装の裁量に落ちた判断がどれだけあるかの読み取りになる。
periplus はまずコメントの描きすぎを防ぐ道具であり、その次に設計と実装の Gap を探す意図を
持つ。伸びた数はその二つ目に属し、それ自体に対して何かをする必要は無い。

## ADR 0003 のどこが撤回されるか

**0003 は編集しない。**ADR 0020 がログの出口を三つから四つへ置き換えたとき、0003 の
「pick・昇格・破棄」はそのまま放置された。新しい ADR が何を上書きするかを自分の中で述べ、
古い ADR には触らない。レガシーとなった ADR を読ませないことがこの慣行の目的である。

撤回されるもの:

- Decision の「**一時的**に居る場所」「いずれかで**必ず出ていく**」
- Consequences の全体 — 「日誌が空に近いことが正常」「溜まっていることが異常を示すシグナル」
  「棚卸し Skill の中心的な仕事は、出口の見えないエントリを見つけて警告すること」

**MECE の核は残る。**0003 の論証が必要としていたのは「periplus と恒久層に**同時に**存在
しない」ことだけであって、「いつか出ていく」ことではない。定義軸が「未処理という状態」から
「決着の有無」へ移っても、決着した why はコードに、決着していない why はログに、と同じ軸で
切れるため重複は生じない。

## `here` と `docs` の境界

**決着したかで引く。**ログは議論中の記述、docs は決着した決定である。

`docs` の三条件(覆しにくい / 文脈無しでは驚く / 実際のトレードオフの結果)は「決着の試験」
としてそのまま生きる。`unspecified-choices` は定義上まだ決着していないので、最初は `here` に
居るのが正しい。

`here` の根拠は「リポジトリがそれを受ける文書を持っていないから」ではなくなる。ログ自身が
議論の場であるなら、文書の不在で正当化する必要が無い。

反復は歯止めではなく**検出**として残る。同じ主題が二度ログに落ちたことが、設計に本当に穴が
あることの証拠になる。一件は文書を作る理由にならないが、一つの主題に二件はなる。この判断は
`/pp-discuss` の Ending 一箇所に置く — 一件を見て分かることではなく、run を通して分かること
だからである。

## 閾値警告と `warnThreshold` の廃止

0003 の Consequences は「SessionStart での件数報告と閾値警告は、この性質があってはじめて意味を
持つ」と自ら書いていた。その性質が撤回された以上、閾値は根拠を失う。`here` を広く許容すれば
ログは正当に伸び、既定閾値 10 では毎セッション警告が出続けて、警告は風景になって死ぬ。

ステータスラインの色を変える機能も落とす。`[PERIPLUS:N!M]` の数値は `.log.md` と `.pre.md` の
行数にすぎない。`config.json` に残るキーは `criteria` だけになる。

件数報告そのものは残す。ステータスラインを入れていない利用者に数を見せる場所が他に無いため
である。語は `entries pending` から `in the log` に変える — 滞在が正常になった以上、pending は
嘘になる。

**ADR 0015 は上書きしない。**0015:33 は archive をログに混ぜない理由の一つとして「溜まって
いることが異常のシグナルでなくなり、閾値警告が意味を失う」を挙げており、この決定はその閾値を
自分で消す。0015 の決定自体は別の理由 —`.all.md` は測定の器であり出自の混在が分布を読めなく
する(0022)— で立つため、理由が一つ蒸発しても結論は動かない。

## `updated` カラムの削除

行の書式から二つ目のタイムスタンプを落とす。

```
- <created> `<file>:<line>` [<kind>] <the note>
```

当初の理由は「実運用で予想以上に頻繁に切り替わり、区別の器として機能していない」ことだったが、
より強い理由はこの ADR から出る。`updated` が担っていたのは「議論済みか未読か」の区別であり、
それはログがキューであるあいだだけ要る区別である。証拠に議論済みの印は要らない。同じエントリに
再び行き当たることこそが、上で残すと決めた反復の検出そのものになる。

同時に落ちるもの — `/pp-discuss` の「一度議論された entry の議論を蒸し返すな」と、「出ていく
条件を名指ししないエントリを素通しさせるな」の節。どちらも代わりを立てない。用語集からも
「引き金」を落とす。どのコマンドも参照しない語を残せば、次に読む人がそれを執行する。

**移行措置は立てない。**`ROW_RE` は新書式のみを読み、旧行は数えない。`.periplus/` は untracked
で、既に使っているマシンは少ない。二つの archive は `rows()` から一度も読まれないため新旧が
混ざったまま置かれ、0015 / 0018 の「編集されず、決して drain されない」とも衝突しない。

## Considered Options

- **閾値だけ上げる** — 警告の機構を残したまま数字を動かす。ログが伸びる理由が変わったことを
  記録に残せず、次に誰かが「溜まっているから減らせ」と読む余地が残る。
- **`here` のエントリを件数から除いて数える** — 「議論待ち」と「出口なし」を分けて数え、後者
  だけを警告する。現行の素朴な行数計算を捨てることになり、「出口なし」の判定を機械に持たせる
  必要が出る。出口の要求そのものを撤回するなら、分ける対象が消える。
- **`updated` を独立した ADR にする** — 当初の予定。理由が「切り替わりの頻度」から「キューを
  やめたこと」に変わり、この決定の帰結になったため一本に収めた。

## Consequences

`.log.md` の件数は何も判定しない数になる。伸びたことに対する自動の応答は無く、`/pp-discuss` を
いつ走らせるかは利用者が決める。

ログが伸び続けるリポジトリと、記述が捕まっていないリポジトリを、件数だけでは区別できなくなる。
区別が要るときに見るのは `.all.md` の分布であって、`.log.md` の行数ではない。

`.periplus/` は untracked のままであり(ADR 0009)、証拠は書いた本人のマシンにしか無い。共有が
要るものは `docs` に出す道が既にあり、その道が使われていないこと自体が「まだ決着していない」の
意味になる。
