# ソースに残るのは、コードを読んでも分からない外側の事実だけ

`why` は捕獲の41%(44/108)を占め、コードに着弾するもののうち61%にあたる。既定でコードへ行く
四つの種別のうち、量として支配的なのはこれ一つである。44行を性質で仕分けた。

| 性質 | 件数 | 例 |
| --- | --- | --- |
| 地雷(触ると壊れる、コードから読めない) | 8 | `?? 0 を入れると…先に作られた床が選ばれる` |
| 実は external-facts(他所の振る舞い・外の事実) | 8 | `Illustrator と同じ挙動` |
| 設計書に既にある(既存の設計番号を指す) | 7 | `全件が1画面にあることが D12 のガードの前提` |
| コードから読める / 相乗り | 21 | `前後は鏡像なので配列を反転して使い回す` |

**ソースに残す価値が明確なのは地雷の8件だけである。**そしてその8件も、ADR 0025 を通せば芯が
`external-facts` として抽出される。

```
「?? 0 を入れると欠損時に同値化して安定ソートで生成順に落ち、…問題が再発する」
  → 「安定ソートは同値のとき生成順を保つ」   [external-facts] → code
  → 「?? 0 は欠損値を同値化する」            [external-facts] → code
  → 「だから ?? 0 を入れない」               [why]            → periplus
```

残る36行は、コードから読めるか、他の種別に属するか、既にリポジトリの文書にある。`why` を
コードに残す既定は、この36行を通すために置かれていたことになる。

## ADR 0002 の既定を反転する

0002 は「既定では why はコードに残す(pick する)側に倒す」と書いた。**これを反転する。**`why` の
既定の行き先は `periplus` になる。

0002 が可変性そのものについて決めたこと — 判断基準を固定せず、名前の付いた項目として列挙し、
設定で個別に切り替えられる — は動かない。反転するのは既定値一つである。根拠は 0002 自身の
Consequences にある。

> 既定値がそのまま推奨値として機能するよう、既定の組み合わせはそれ単体で筋の通った規律に
> なっている必要がある。

`why` がコードへ行く既定は、この条件を満たしていなかった。

## `block-headings` を drop から code に動かす

同時に `block-headings` を `code` にする。ラベルが指すブロックが大きいとき、ラベルは働く。

**これだけは外側の事実ではない。**`block-headings` が指しているのはコードそのものであり、この
決定の題に当てはまらない。例外として置く。

正当化の代わりに、疑う条件を書く。ブロックが小さければラベルは `tautology` と区別がつかず、
区別がつかないなら drop に戻すべきである。ブロックの細分化はコードの問題であり、規律はコードを
直さない(ADR 0021)。**したがってこの例外は、コードの側が悪いほど効くという筋の悪さを持って
いる。**ADR 0025 が体言止めを `block-headings` に寄せるので着弾はその分増える。増え方が観測でき
たとき、最初に疑うのはこの一行である。

## 行き先は 4/4/4 に揃う

```
code     : external-facts, contracts, current-limits, block-headings   ← 外側の何か
periplus : why, unspecified-choices, rejected-alternatives, upgrade-triggers  ← 未決の設計
drop     : tautology, doc-references, history, test-intent             ← 他所から復元できる
```

上の例外を除けば、**ソースに残るのはコードを読んでも分からない外側の事実だけ**という一行で
説明できる形になる。

## Considered Options

- **語彙で免罪符を検出して drop に送る** — 「念のため / 一応 / 万が一 / 安全のため / とりあえず
  / 後方互換 / 必要に応じて」を拾う案。**コーパスで0件。**免罪符は字面に現れず、やりすぎた説明
  として文章全体に表出する。行単位では検出できず、ファイルあたりの着弾密度にしか出ない(下の
  `floorOrder.ts`)。語彙リストは必ず漏れ、漏れた分だけ「リストに無いから通した」という別の
  免罪符を生む。
- **`why` を残し、地雷だけを拾う種別を足す** — 種別の集合は閉じている(ADR 0014)。加えて地雷は
  ADR 0025 を通せば `external-facts` に分解されるので、新しい名前は要らない。
- **既定を動かさず、量は `/pp-discuss` の運用で吸収する** — 差分がゼロになる。着弾密度の過剰は
  行単位の種別判定では捕まらないので、運用に回した分はそのまま残る。

## Consequences

コーパスに当てた場合の着弾数。体言止めの `block-headings` への再分類は含まない。

```
                     捕獲   → code着弾(現行) → code着弾(新)
全体                  108        72 (67%)         28 (26%)
floorOrder.ts          22        13                5
index.tsx              17        14                3
useFloorReorder.ts     21        15                8
templates_controller    4         3                0
```

`floorOrder.ts` は50行前後のファイルに13件が着弾していた。二行に一コメントである。これが十行に
一件になる。**一件ずつ見ればどれも妥当なのに、束ねるとドキュメントになっている**という過剰は、
行単位の種別判定では捕まらない。行き先の移動でしか落ちない。

28件は過小評価である。ADR 0025 が体言止めを `block-headings` に寄せ、この決定がそれを `code` に
送るので、いま `tautology` として破棄されている行の一部がソースに着く。二つの決定が逆向きに効く
唯一の場所であり、実測は実装後の `all.csv` を待つ。

ログは太る。`/pp-discuss` の扱いは変わらない — 量の変化であって規則の変化ではない。

`why` をコードに残したいリポジトリは `config.json` で戻せる。ADR 0002 が作った可変性はそのために
ある。動かしたのは、既定が推奨値として機能するかどうかだけである。
