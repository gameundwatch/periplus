# セッション開始時に注入するのは捕捉の規則だけにする

規律全文をセッション開始時に注入すると約1,630トークンかかり、これはコードを一行も
書かないセッションでも、各サブエージェントの起動でも払われる。一方で判断基準の表と
フィルタ手順が必要になるのは、タスクの最後に一度だけ実行されるフェーズ2のときに限る。

そこで注入対象を SKILL.md 内の `always` 領域 — フェーズ1の捕捉規則と、完了前に
`/pp` を呼べという指示 — に絞り、残りは `/pp` が呼ばれたときに読み込ませる。注入は
306トークンになった。文言は SKILL.md から切り出しているため、常時の規則と `/pp` の
本文が別々の規律に分かれることはない。

## Considered Options

- **散文をさらに削る** — 150行をより短くする。実測では注入本文は差分の23%でしかなく、
  残りは退避と振り分けの作業そのものだったため、削っても効果が小さい。
- **サブエージェントへの注入をやめる** — 固定費は半減するが、委譲先で規律が切れる。
- **リポジトリ単位の opt-in** — 使わないリポジトリでの固定費がゼロになる。段階的読み
  込みと排他ではないため、必要になれば後から併用できる。

## Consequences

判断基準の表が注入されなくなったため、`.periplus/config.json` による上書きは hook が
描画して届けるのではなく、フェーズ2でモデルが設定ファイルを読むことで反映される。
機構による保証から指示による依頼に変わっており、設定ファイルが存在するリポジトリでは
その旨を起動時の一行で知らせている。

フェーズ2に到達しなければ判断基準は一度も読まれない。捕捉した記述が未処理のまま残る
失敗は、以前から pre.md の件数報告で警告している。
