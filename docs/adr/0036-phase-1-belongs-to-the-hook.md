# phase 1 は hook のもので、`/pp` は phase 2 だけを走らせる

ADR 0033 は `/pp` に `/pp-capture` → `/pp-classify` → `/pp-resolve` を通させた。理由は「名前が
periplus そのものである以上、覆うのは規律の全体である」だった。

`/pp` が走る時点で捕捉は終わっている。第一段が読み込む 1,781 字は `pre.csv` を一行も増やさない。
**再実行されているのは規則の読み込みだけで、phase 1 そのものは一度しか走っていない。**

0033 が見ていなかったのは、規則を文脈へ入れる役が phase ごとに違うことである。

| | phase 1 | phase 2 |
| --- | --- | --- |
| 規則の在処 | 捕捉規則 | `pp-classify` + `pp-resolve` |
| **規則を文脈へ入れるのは** | **hook**(常時) | **`/pp`**(1 度) |

0033 は 1 行目の並びをそのまま実行順にした。**規律の全体を覆うことと、状態を手続きの列に混ぜる
ことは別である。**

## 決めたこと

`/pp` は `/pp-classify` → `/pp-resolve` の二段になる。phase 1 は hook が撃っていると述べるだけに
する。**ADR 0033 の表題はこの ADR が置き換える。**覆う範囲は変わらない。変わるのは、覆うことを
本文の読み直しで果たさないことである。

捕捉規則は skill を降りて `hooks/capture.md` になる。読み手は hook だけになり、description が毎
セッションの skill 一覧から消える(149 字、ADR 0034 の実測)。

## hook が死んでいる場合の経路を諦める

0033 の Consequences は「hook が効いていないとき、それを継がなかったサブエージェントで、`/pp` を
呼べば捕捉規則が入る」と書き、同じ段落で「実際の穴は狭い」と書いている。
`SessionStart(startup|resume|clear|compact)` と `SubagentStart` で撃つので、残るのは node が無い・
タイムアウト・hook 無効の三つである。

そのうえ効くのは**まだコードを書いていない**場合に限られる。書いた後に捕捉規則が届いても窓は閉じ
ており、そこでの復旧は `/pp-refactor` であって捕捉規則ではない(ADR 0017)。

狭い一点のために、`/pp` のたびに本文一つぶんを払っていた。

## Considered Options

- **注入を薄くする(ポインタ)** — 規則の在処だけを注入し、本文は必要になってから読ませる。
  v0.7.7 の試験では 4 回とも現行より遅く、合計 +7.1% だった。**問題は注入側ではなく呼び出し側で
  ある**
- **`/pp` に捕捉規則を再掲する、あるいは一体化する** — hook が死んでも `/pp` だけで規律が立つ。
  二重払いが恒久化し、ADR 0007 の `always` 領域方式に戻る。買えるのは上の狭い一点で、そこは
  `/pp-refactor` が既に覆っている
- **`skills/pp/CAPTURE.md` に戻す**(v0.7.1 の形) — ADR 0032 が「`skills/` の外に置く」を却下した
  理由は「`/pp` から見て phase 1 がどこにあるかが遠くなる」であり、`/pp` が phase 1 を持たなく
  なれば消える。0032 の表題に従えば、phase 1 を走らせているのは hook である

## Consequences

`/pp` が読む本文は 11,946 字から 10,280 字になった。第一段の 1,781 字が消え、`skills/pp/SKILL.md`
が phase 1 の在処を述べるぶん 115 字増えている。毎セッションの固定費は description の 149 字ぶん
減る。

`disable-model-invocation` の論点が消える。skill でないファイルは Skill ツールから呼べないので、
ADR 0033 と 0034 がこの旗を巡って書いた検討は掛かる先を失う。

`/pp` から phase 1 がどこにあるかは見えなくなる。`hooks/capture.md` を指しているのは hook の
`CAPTURE_PATH` と README だけである。

**`/pp` が何段を名指ししているかを見るテストは無いままである。** 0033 は v0.7.1 の変更が記録され
ずに通った原因をそこに見ていた。この ADR も塞いでいないので、次に同じ壊れ方をしたとき落ちるもの
は無い。
