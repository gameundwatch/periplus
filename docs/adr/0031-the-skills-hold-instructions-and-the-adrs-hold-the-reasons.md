# 手順書は命令だけを持ち、理由は ADR が持つ

v0.7.0 の作業を始めた対話で、モデルが同じ誤りを二度犯した。`kind` と行き先を混同し、
「四つの kind の既定が同じ periplus だから、この区別は何も変えていない」と論じた。ADR 0014
が語を二つに分けた理由そのものを踏み外している。

**原因は読み手側ではなく文面側にあると見る。**同じ誤りが二度出るなら、それは誤読ではなく
誘導である。この版は文面を削るが、削る目的はトークンではなく**誤読の余地**である。軽くなる
のはその結果にすぎない。

誘導している箇所は特定できた。

- `skills/pp/SKILL.md:213-218` — 一つの表に二つの語彙が同居し、`code` が一行の中で二つの
  意味を持つ。左は「rows whose kind sent them to periplus」— kind が送ったという言い方 —
  で、右は `/pp-discuss` の `docs, code, or trash` である。`CONTEXT.md:153-155` は「別の
  語彙である」と明記しているが、**その断り書きは設計文書にあって、モデルが読むファイルには
  無い**
- `skills/pp/SKILL.md:226-247` — kind 表の百行下に、二セット目の行き先語彙が節として立つ
- `skills/pp-classify/SKILL.md:35-37` — `config.json` を読むなという規則が、その理由として
  `history` の行き先を書いている。規則が自分の禁止事項を実演しており、しかも `history →
  drop` はこのリポジトリの既定にすぎない
- `skills/pp-discuss/SKILL.md:15-17` — 既定の routing を kind 名五つで焼き込んでいる。
  `config.json` を変えたリポジトリではこの文は偽になる。ADR 0029:180-182 はこの一文を
  「ADR 0026 に追随しなかった二箇所」として直しており、**同じ一文が既に二度ずれている**

## SKILL.md は実行手順書であり、README.md が説明書である

`skills/*/SKILL.md` はそのコマンドを実行するための手順だけを持つ。periplus 全体が何であり
なぜそうなっているかは `README.md` が持ち、個々の決定は ADR が持つ。

この役割分担は今まで宣言されていなかった。`skills/pp/SKILL.md` が両方を兼ねていたため、
`/pp` の流れに一度も現れない `docs` / `here` / `trash` の語彙が、`/pp-classify` が kind を
決めている最中も文脈に居座っていた。上に挙げた四箇所は、いずれもこの兼務から出ている。

## 剪定の規則は「消して実行結果が変わるか」

一文を消したとき、手順の実行結果が変わるなら手順の一部であり、残す。変わらないなら
`doc-restatement` か `why` であり、ADR が既に持っている。

例を三つ挙げる。`skills/pp/SKILL.md:143-159` の「1 は 3 より前」「5 は 6 より前」の弁明は、
消しても順序表 `133-141` が残るので実行結果は変わらない。ADR 0029:95-103 が同じ内容を
持っている。落とす。`121-125` の「`current-limits` と `upgrade-triggers` は対で来る」は、
消すと一件を割らずに通す確率が上がる。実行結果が変わる。残す。`258-274` の Configuration
は `/pp` の手順に含まれない。落とす。

## 手順書に理由は書かない

原則として、理由は手順書に残さない。**「X せよ、なぜなら Y」は「ここでは Y が当たらない」
という反論の足場を作る。**裸の命令には足場が無い。判断の余地を残すことは、この規律では
利点ではない。

`always` 区間も例外にしない。ここは毎セッション注入され、`/pp-refactor` の四十七倍の頻度で
読まれる。命令に勝たせるために弁明が要るという主張は立つが、足場を与えるほうが負ける。

### ADR 0007 の追記が置いた削除条件は、材料が無く判定できない

ADR 0007:30-41 は 2026-07-30 に `always` 区間へ三段落を足している — 永続節、引き金を
繰り上げる段落、完了ゲート。理由は「規律がそもそも発火していなかった」ことで、削除の条件を
「三段落が発火率を上げなかった場合」と書いた。

**その比較はできない。**当時の作業ファイルは `.pre.md` であり、`all.csv` は 2026-08-02 の
CSV 化(44a17c4)以降しか持たない。前後で数えられる同じ形の記録が存在しない。

そこで別の根拠で判定する。0007 が足した三段落は、**三つとも命令部分が残る**。永続節は全文が
命令である。引き金は「The trigger is writing code, not the arrival of a sentence」が残り、
「by the time a comment is forming…made wrong」だけが落ちる。完了ゲートは「pre.csv に行が
ある間タスクは終わっていない」と「どちらだったか報告せよ」が残り、周囲の八行が落ちる。

落ちるのは弁明だけで、0007 が発火率のために買ったものは残る。

## Considered Options

- **二つの語彙を明示的に区別する二〜三行を `skills/pp/SKILL.md` に足す** — 誤読は直るが
  行が増える。しかも語彙を二つ持つこと自体は変わらないので、次の追随漏れは同じ場所に出る。
  `skills/pp-discuss/SKILL.md:15-17` が二度ずれたのは、断り書きが無かったからではなく、
  持ち主が二人いたからである
- **理由を手順書に残し、ADR への参照だけを添える** — 「詳細は ADR 0029」と書けば根拠は
  辿れる。ただし参照は `doc-restatement` の定義そのものであり、このリポジトリはそれを
  既定で `drop` に置いている。自分の規律が捨てる形式を、自分の手順書が使うことになる
- **`always` 区間だけ例外にする** — 割り込みの文章は説得力を要するという主張には理がある。
  ADR 0012 が言うとおり機構による強制が無く、散文だけが規律を支えているので、剥がした結果
  発火率が落ちる可能性は実在する。それでも足場を与えないほうを採る
- **何もしない** — 混同は対話の中で訂正できた。ただし訂正したのはユーザーであり、二度とも
  そうだった

## Consequences

五つの SKILL.md 全部に当たる。`skills/pp/SKILL.md` は 274 行から約 197 行、`always` 区間は
47 行から約 32 行、残り四つで約 150 行。合計 818 行が約 590 行になる。

`/pp` を読んだだけでは、periplus に送った行がその後どうなるかが分からなくなる。それは
`/pp-discuss` と `README.md` が持つ。

**発火率が落ちたら戻す。**0007 と違い、今度は測れる — `all.csv` の日次件数が、コードを
書いた日に対して落ちるかを見る。0007 が比較の材料を持たなかったのは記録形式が変わったため
であり、CSV になった今は同じ形で数えられる。

切り分けも要らない。発火率を動かしうるのは `always` 区間だけであり、残り四つのファイルは
全て phase 2 で、`/pp` を呼んだ後にしか読まれない。捕捉が起きるかどうかには関与しない。
`always` 区間の変更を一つのコミットに分けておけば、それだけを戻せる。

`hooks/periplus-activate.test.js` が三つの制約を持っている。CSV 行形式は README と四つの
SKILL.md の全部に書かれていなければならない(`:302`)。`delivered × 3 < skill` の比率が要る
ので、`pp/SKILL.md` を `always` 区間より速く削ることはできない(`:270`)。実測 `2693×3 <
13770` に対し、この版の見積りは `1868×3 < 9535` で通る。順序表 `133-141` は
`the kinds the table cannot separate are separated somewhere`(`:230`) を満たすので、その下の
弁明は落とせる。

ADR 0012 が名指しした危険がこの版に直接かかる。散文で頼む以上、削った散文の分だけ規律は
他の文言に負けやすくなる。0012 は「スキルに例外を作る一文を書くときは、常時注入されている
規則のどれを緩めるのかを確かめよ」と書いた。この版は例外を作るのではなく理由を落とすので、
緩む規則は無い — というのがこの ADR の主張であり、外れうる主張である。
