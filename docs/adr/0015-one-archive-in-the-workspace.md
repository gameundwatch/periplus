# `.all.md` を置く。`.periplus/` に許す唯一の archive とする

ADR 0003 は periplus を内容の種類ではなく状態として定義し、置かれた記述は必ず出ていく
と定めた。日誌が空に近いことが正常であり、溜まっていることが異常のシグナルになる、
という性質はこの定義から来ている。

`.all.md` はこの定義に反する。一度でも `.pre.md` に入った行を全て複写し、そこから何も
出ていかない。純然たる archive である。それでも置く。

理由は、種別が記録として残らないからである。種別が書き出されるのは periplus 行きの
記述だけで、コードと破棄に行った記述の種別はその場で消える。結果として、どの種別の
コメントが何件書かれているのかを誰も数えられない。`history` が定義上ソースに一行も
残らない以上、利用者はその種別の実例を目にする機会すら持たない。

規律が効いているかどうかを測る方法が存在しない、という状態を放置するほうが、例外を
一つ開けるより悪い。ADR 0013 が時制テストを保留したのも、`.all.md` で実測してから
決めるという前提に立っている。測る場所が無ければ、あの保留は永久の先送りになる。

## 行き先の列は作らない

`.all.md` が持つのは 作成日時・更新日時・場所・種別・本文 だけで、行き先は持たない。
行き先は種別と `config.json` から常に引けるものであり、複写すれば設定を変えた瞬間に
食い違う第二の情報源になる。これは `drop` の根拠(コード・git log・ADR から復元できる
ものを二重に持たない)と同じ論理である。

`.all.md` が答えるべき問いは「どの種別が何件書かれたか」であって、配送の監査ではない。

## Considered Options

- **`.pre.md` に入った時点で複写する** — 元の案。ただし捕獲時点ではまだ種別が無いため、
  複写しても分類のデータにならない。種別・行き先・本文が揃うのは配送の瞬間だけである。
- **`.log.md` を archive 化して兼ねる** — ファイルは増えないが、ADR 0003 の性質を日誌
  そのものから奪う。溜まっていることが異常のシグナルでなくなり、閾値警告が意味を失う。

## Consequences

`.periplus/` の中に、出ていかないファイルが一つできた。ADR 0003 の「置かれた記述は必ず
出ていく」は、以後 `.pre.md` と `.log.md` についての言明として読む必要がある。

`.all.md` は無限に伸びる。gitignore されているため各利用者の手元にだけ溜まり、共有され
ない。実行中にこれを読む処理は無く、読まれるのは規律そのものを見直すときだけである。

`/pp-refactor` が集めた既存コメントもここに入る。他人が書いたコメントであり、掃除を
一度走らせれば種別の分布は動く。`.all.md` を「この規律の下で書かれたコメントの姿」と
して読むときは、掃除の有無を思い出す必要がある。列を足してこれを区別する案は採らな
かった — 上の「行き先の列は作らない」と同じ理由で、ファイルを重くする。

**この最後の段落は ADR 0018 で覆された。** 掃除が切り取りになり(ADR 0017)、範囲内の
コメントを全部刈るようになったため、注意書きでは足りなくなった。掃除の分は
`.periplus/.swept.md` に落とす。「`.pre.md` に入った行は必ず `.all.md` を通る」は
「`.pre.md` を出た行は必ず archive に着く」に置き換わり、archive は二つになった。
列を足さないという判断はそのまま生きている — 出自はファイルの違いが言う。
