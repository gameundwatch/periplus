# pre-comment は書き留める時点で、種別が一つに定まる最小単位まで分割する

ADR 0004 は「分割してから分類する」を定め、分割を phase 2 の最初の手順に置いた。
それでも混在は残った。分割が phase 2 で行われる限り、`.pre.md` には既に混ざったものが
積まれ、分割の質は数十件を一度に処理する終盤の注意力に依存する。

そこで分割を捕獲側へ押し出す。一つの pre-comment は一つの種別を持ち、複数種別は
許さない。二つ持つように見えるものは一つの記述ではなく、まだ割られていない二つの
記述である。

phase 1 に足す規則は一つだけにした。

```
逆接・並列で二つを繋いだら二行に割る。因果(〜のため)は一件のまま。
```

因果だけが割れないのは `why` が因果そのものだからである。「タイムアウトが多発した
ため非同期にした」は原因と結果を切り離せば why が消える。逆接・並列は種別の違う
二つを接続詞で縫っているだけで、縫い目に意味が無い。

## これは ADR 0006 と競合する

ADR 0006 は「書いている最中の判断はコードに向けるべき注意を食う」を理由に、捕獲を
`as it came to you`、`do not decide where it belongs` と定めた。分割は程度の差はあれ
行き先の決定を捕獲側に持ち込む。

競合は認めた上で、線を「粒度」と「分類」の間に引いた。捕獲が守るのは粒度だけで、
種別の語彙は phase 1 に一切現れない。逆接か因果かの判別に判断表は要らず、コードから
注意を奪う量は一文の追加に収まる。分類そのものは `/pp-classify` に残り、そこで一つの
種別に落ちなければさらに割られる。捕獲の粗い網と、分類の精密な網の二段構えになる。

## Considered Options

- **複数種別を許し、行き先が割れたらエラーにする** — 機械的に検出できる点は優れて
  いたが、行き先は設定で変えられるため、どのような割れ方も正当でありうる。エラーに
  すると利用者の設定を否定することになる。
- **複数種別を許し、優先規則で解決する(code が勝つ)** — ADR 0004 が既に検討して却下
  している。差分は最小だが、混在という根本原因が残る。
- **時制テストも捕獲側に足す**(過去の状態と現在の性質が同居していたら割る) — 捕捉できる
  ものが逆接・並列の下位集合であり、注入テキストを二重に膨らませる。運用後に `.all.md`
  で history の混入件数を見てから判断する。

## Consequences

`.pre.md` の行は種別の欄を持ち、捕獲時点では空になる。空欄が残ったまま配送された行は
存在しえないので、濾し残しが機械的に見えるようになる。

捕獲の負担は増える。増えた分は、終盤に混在した記述を割り直す作業から移ってきたもので
あって、総量が増えたわけではない — という想定であり、これは検証されていない。捕獲時の
分割が雑になれば `/pp-classify` の split 件数として現れる。
