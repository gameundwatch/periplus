# 理由は「誰が決め、どこが記録しているか」で分ける。`why` は残余になる

ADR 0026 が `why` の既定を periplus に倒した後、`/pp-discuss` で「文書から容易に復元できるため
trash」という判断が急増した。この版はその急増を扱う。

**濾過は故障していない。**`/pp-discuss` は正しく判定している。誤っているのは配分で、機械的に引ける
判定に合意の対話を使っている。`/pp-discuss` は一件ずつユーザーの合意を取る場であり(ADR 0012)、
「ADR 0028 に書いてある」は合意を要する判断ではなく事実確認である。

自リポジトリの実測 68行(`all.csv` 18 + `swept.csv` 50)。

| kind | 件数 |
| --- | --- |
| `why` | 24 |
| `doc-references` | 1 |
| `unspecified-choices` | 0 |

## 種別の名前は主題を指すが、二つが文の形を指していた

ADR 0014 は「名前はコードの属性ではなく記述の主題を指す」と定めた。この版で見つかったのは、その
規則の**別の破れ方**である。二つの種別が主題ではなく**文の形**を名乗っていた。

`doc-references`(参照)は形で定義され、**発火しなかった**。唯一の1件すら定義どおりではない。

```
.periplus/all.csv:16  hooks/periplus-activate.js:127  doc-references  "種別の集合は閉じている"
```

これは ADR 0014 が持っている内容であって、文書へのポインタではない。表の定義と、分類器が実際に
撃っているものが既に食い違っていた。

`why`(理由)も形で定義され、逆に**吸いすぎた**。0026 のコーパスで 44/108、`swept.csv` で 21/50。

ADR 0026 は drop の四つをこう並べていた。

```
drop : tautology, doc-references, history, test-intent  ← 他所から復元できる
```

`tautology` はコードから、`history` は git log から、`test-intent` は describe/it から復元できる。
四つは**復元元**で組織されている。`doc-references` だけが軸が違い、その一つだけが発火していない。

## `doc-references` → `doc-restatement`

定義を「このリポジトリの既存の文書が既に書いている記述」に広げ、改名する。字面のポインタ
(「ADR 0007 参照」)は新しい定義に含まれるので取りこぼしは無い。

**改名するのは、機能しなかった原因が名前の側にあるからである。**定義文だけを広げても、「参照」と
いう字面はこの先もポインタを引き寄せ、内容の重複を弾く。0014 が `history` → `legacy` を却下した
ときに名指しした故障機構が、逆向きに働いている。

0014 は改名を「警告なく無効化される」ことを理由に却下したが、その沈黙は 0014 自身が同じ版で潰して
いる。未知のキーは `config.json: unknown kind "..."` として報告される。種別キーの改名はもう静かでは
ない。

## `undocumented-design` を足し、`why` を残余にする

`why` が抱えていた残りは、**誰が決めたか**で割れる。

| | 決めた者 | 記録 |
| --- | --- | --- |
| `doc-restatement` | — | 文書が持っている |
| `undocumented-design` | 設計 | どの文書も持っていない |
| `unspecified-choices` | 実装 | どこにも無い |

`unspecified-choices` は動かさない。0/68 の原因は隣の `why` が先に吸ったことで説明でき、その吸引は
`undocumented-design` が前に立つことで消える。名前を疑うのはこの版の後も0件が続いたときである。

**`why` は残余として存続する。**名前・定義文・設定キーは据え置き、位置だけが最後になる。判定材料
(ADR 0022)は「設計が決めていない」を積極的に言えないことがあり、0022 はその不確定を
`unspecified-choices` に落としていた。それは推測を分類として記録することだった。残余があれば
推測せずに済む。**判定できなかったことを判定できなかったまま記録する場所**である。

種別は 12 から 13 になった。ADR 0014 は**上書きしない** — 0022 と同じ経路であり、閉じているのは
利用者が設定で足せないことであって項目数ではない。硬直性は働いた。種別を一つ足すのに版と ADR を
要した。

ADR 0026 の 4/4/4 は 4/5/4 になる。「ソースに残るのはコードを読んでも分からない外側の事実だけ」は
そのまま成り立つ。

## 読む順序

表は 4・5・6 を分けられない。分けるのは順序であり、順序は `skills/pp/SKILL.md` の表の下、一箇所に
置く。

```
1. 消えると次の読み手がコードを壊せる       → external-facts / contracts / current-limits
2. 目の前のコードが既に示している           → tautology
3. 文書と行を名指しできる                   → doc-restatement
4. 設計が決めた理由で、どの文書も持っていない → undocumented-design
5. 設計が決めていないと積極的に言える        → unspecified-choices
6. 4 とも 5 とも判定がつかない理由           → why
```

**1 は 3 より前である。**文書化済みの外部事実が 3 に吸われると、0026 が数えた「地雷8件」がコードから
消え、ADR 0004 が防いだ「次の読み手が善意で壊す」が戻る。この規則は行き先の語彙を使わずに言える —
**その記述が消えたとき次の読み手がコードを壊せるか**。壊せるなら主題はコードの外側の事実・契約・
限界であり、それを別に書いた文書があることは主題を変えない。

**2 は 3 より前である。**証拠が近いほうを採る。加えて 2 の試験は無料で、3 は検索を伴う。

**5 は 6 より前である。**5 は積極的な証拠を要求する試験であり、通らなければ自動的に 6 に落ちる。
逆順にすると残余が先に立ち、5 は永久に0件のままになる。

### 判定材料は永続記録に限る

**セッションは 3 の根拠にならない。**ADR 0022 が第一段にセッションを置いたのは「設計が決めたか」を
判定するためで、セッションは決定の発生源として有効だった。3 が問うのは「後から読み返せる場所に
既にあるか」であり、セッションは消える。口頭で言われただけの理由はどの文書も記録していない理由で
あり、4 である。

**文書名と行番号を名指しし、その行が同じことを述べていること。**違うことを述べているなら言い直し
ではない。文書が古く記述のほうが正しい場合はこれで弾かれ、記述は 4 か 6 に落ちて失われない。

引用は `/pp-classify` の報告行にのみ現れ、保存されない。行番号は文書内で動くが、保存されないので
安定性は問題にならない。行まで求める意味はそこにある — 文書名だけなら「たぶん ADR のどこかに
ある」で通る。行を出せというのは、実際に見つけたことの証明を要求する装置である。

CSV の形式は変えない。引用列を足すと行が自分の出自を持つことになり、一つの形式を四つのファイルで
共有している性質が崩れる。

### 検索は候補行ごとに行う

`/pp-discuss` が冒頭で棚卸しするのは(ADR 0020)、**行き先の文書を名指しで提案する**には在庫を知って
いる必要があるからで、あれは目録の仕事である。ここで必要なのは「この主張がどこかに書かれているか」
の検索であり、目録を先に読んでも検索は減らない。28本の ADR を頭に入れてから3行を分類するのは規律
ではなく儀式である。

`/pp-classify` が `config.json` を読まない規則(ADR 0014)は変わらない。読むようになるのは文書だけで
ある。

## install は欠けているキーを既定値で追記する

`.periplus/` は追跡外なので、手で配られた設定が現場にある。改名後、そこに `doc-references` が
書かれていると警告が出てそのキーは既定に落ちる。

**install は既存キーに触らず、`DEFAULT_CRITERIA` にあって `config.json` に無いキーを既定値で追記
する。**

これは意味論的に何も変えない操作である。キーが無い状態と、キーが既定値で書かれている状態は
`loadConfig` から見て同一だからである。したがって「設定ファイルを黙って書き換える」の危険 —
利用者が選んだ値が変わる — が構造的に起きない。旧キーには触らないので、`doc-references: code` と
設定していた人の意図を推測する必要も無く、警告がそのまま「これは効いていない、消せ」の通知になる。
必要なのは知らせることであって、勝手に直すことではない(ADR 0014)。

**改名専用の仕掛けではない。**ADR 0022 で `unspecified-choices` が増えたとき、既に存在した
`config.json` はそのキーを永久に持たなかった。同じ穴が塞がる。

パースできない `config.json` は書き換えない。欠けたキーが無ければ書かない — 整形の往復で利用者の
ファイルが変わるためである。

警告文も直した。`config.json ignored — unknown kind "..."` は設定ファイル全体が無視されたと読める
が、実際に落ちるのはそのキー一つだけである。この経路は今までほぼ発火しなかったが、今回の改名が
初めてこれを多数の利用者に見せる。

## Considered Options

- **13番目の種別として「文書から復元できる why」を足す**(当初案) — `doc-references` の修復で足りる。
  0014 を上書きする議論を、既存の一項目が狭く書かれていただけの場所で発動させることになる。
- **`doc-references` の定義だけを広げ、改名しない** — 既存 `config.json` が無傷。ただし発火しなかった
  原因である名前が残り、症状だけを直す形になる。
- **`unspecified-choices` を `why` に改名する**(検討された案) — 弁明は「〜なので」という理由の文で
  書かれるので、名前は文の形と一致する。だがそれこそがこの ADR が故障として扱っているものであり、
  いま剥がした吸引力をより狭い側に付け替えることになる。
- **何もしない** — trash 急増は 0026 が受け入れた帰結であり、出力は正しい。合意の対話が事実確認に
  使われ続ける。

## Consequences

`/pp-refactor` にはセッションが無いため 5 の積極的証拠がほとんど揃わず、既存コードの理由は `why` に
落ちる。ADR 0022 は「誤検出は出るが、既存コードの未決着な設計判断を掘り出せることのほうを採る」と
書いており、**その掘り出しは弱まる。**失うのは分類の解像度だけで、行き先は 4・5・6 とも periplus の
まま変わらない。0022 が受け入れた誤検出を、代わりに「判定できなかった」と正直に記録する形になる。
この後始末は v0.6.1 で行う。

**表だけを読むと 4・5・6 は見分けがつかない。**区別は全て順序が担い、順序は散文一箇所にある。この
設計で最も脆い一点であり、次にこの三つの分布が崩れたとき最初に疑うのはこの一箇所である。表の下に
その節が存在することはテストで固定した。

ADR 0026 が `why` を periplus に倒したとき追随しなかった二箇所 — `skills/pp-discuss/SKILL.md` の
「Three kinds route here by default」と `CONTEXT.md` の「三つで」 — をこの版で直した。どちらも五つに
なる。
