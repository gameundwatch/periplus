# periplus は内容の種類ではなく「未処理」という状態として定義する

コード・コメント・ドキュメントは内容が重複せず MECE であるべきという方針を採り、
かつ設計・方針・why は既定でコードに残す(pick する)と決めた。この2つを同時に
満たすには、periplus を「why を持つ層」として定義することができない。そこで
periplus を内容の種類ではなく**状態**として定義する。periplus は「まだ行き先が
決まっていない記述が一時的に居る場所」であり、置かれた記述は pick・昇格・破棄 の
いずれかで必ず出ていく。ある記述が periplus と恒久層に同時に存在する瞬間は無い
ため、内容が何であっても MECE は破れない。

## Consequences

日誌が空に近いことが正常な状態になり、溜まっていることが異常を示すシグナルに
なる。SessionStart での件数報告と閾値警告は、この性質があってはじめて意味を持つ。

逆に、エントリに出口(pick されるのか、昇格するのか、破棄されるのか)が無い場合、
それは状態としての定義を裏切る永久在庫になる。棚卸し Skill の中心的な仕事は、
出口の見えないエントリを見つけて警告することになる。
