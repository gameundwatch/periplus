# コメントを書いてから回収する方式は採らない

実装中の退避を省き、コメントを通常どおりソースに書いてからフェーズ2の直前に grep で
`pre.md` へ回収する方式を、トークン削減の候補として実装し測定した。既定方式より高く
つき、ログも痩せたため削除した。

2タスク3構成の実測（対 未使用時）:

| | 既定 | 回収方式 |
|---|---|---|
| retry | 1.17x / ログ3件 | 1.35x / ログ2件 |
| cap | 1.37x / ログ5件 | 1.62x / ログ4件 |

高くなる理由は工程数にある。既定は「pre.md に書く → 濾す」の2工程だが、回収方式は
「ソースに書く → 読み直して写す → 濾す → ソースを書き直す」の4工程になる。退避を省いた
のではなく往復を増やしていた。

ログが痩せるのは事前に予測できていた。grep はコメントとして書かれたものしか拾えず、
却下したライブラリや気づいて通り過ぎた天井といった、ソースには書かないが記録に値する
記述が落ちる。実測では既定が15〜21件を退避したのに対し、回収方式は13〜14件だった。

もう一つ観測されたのは、一度ソースに書いた散文は短くしにくいという点である。同じ内容が
既定では2行、回収方式では4行になっていた。書く前に濾すことに、書いた後で濾すのとは別の
効果があることを示している。

## Consequences

`.periplus/config.json` の `capture` は削除された。トークン削減の手段として残るのは
セッション開始時の段階的読み込み（ADR-0007）のみで、変動費にあたる退避と振り分けの
作業量は規律そのものであり、削れば規律が弱まる。
