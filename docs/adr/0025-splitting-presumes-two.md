# 分割は推定有罪とし、すべての行が主語を持つ

periplus を実運用しているリポジトリの `all.csv` 108行を読んだ。**25行(23%)が2文以上のまま
`/pp-classify` を通過している。**そのうち割るべきでなかったのは3行で、残る22行は種別が二つ
以上混ざったまま一行に収まっていた。ADR 0013 が捕獲側に粗い網を置き、`/pp-classify` に精密な
網を置いた二段構えの、両方をすり抜けている。

混在は三つの型に分かれる。

| 型 | 件数 | 何が起きているか |
| --- | --- | --- |
| A. 相乗り | 14 | 「コードが何をするか＋理由/外界の事実」。強いほうの種別が付き、tautology の半分がソースに着弾する |
| B. history 巻き添え | 3 | 経緯と事実が束。丸ごと `history` に落ちて破棄され、事実が消える |
| C. 同一種別が2件 | 5 | 別々の why が一行。現行規則では原理的に検出できない |
| D. 因果が文をまたぐ | 3 | 割るべきでない。正常 |

## 立証責任を、割らない側に移す

現行の規則は推定無罪である。

```
For each empty row, try to name its kind. If two names fit, the row is two rows.
```

二つ名付けられて初めて割る。この形は二つの穴を持つ。「これは因果だから一件」という自己弁護を
許すことと、型Cを原理的に検出できないことである。型Cは同じ種別が二つ並んでいるので、二つ
名付けようとしても一つしか出てこない。

**hard stop は「一行一種別」のまま動かさず、立証責任だけを反転する。**接続点があれば割る。
割らないのであれば理由を述べる。判定の主語は名付けられた種別の数ではなく、その行が含む主張の
数である。

## 主語の欠落が、種別を借りさせている

型Aの原因は文法にある。108行のうち27行(25%)が主語を持たない節で終わっており、**主語の無い
断片は自分の種別を主張できないので、隣の種別を借りる。**

```
[external-facts] 「update_all はモデルを更新しないので a.floor_layer_index は古い。割り当てた値をそのまま返す」
                  └ 主語あり = external-facts ───────────────┘ └ 主語なし ────────┘
```

第二節に主語を補うと「このアクションは割り当てた値をそのまま返す」— コードが言っていること、
つまり `tautology` である。主語が無いまま隣にいたので `external-facts` の種別を借り、ソースに
着弾した。

そこで **`/pp-classify` は各行に主語を補い、補った結果として種別を名付ける。**これは分割規則
ではなく、種別の誤判定の検出器である。主語を補った瞬間にその行が何について語っているかが確定
し、tautology が tautology として露出する。

補完を捕獲側に置かないのは、ADR 0007 と ADR 0013 が引いた線を越えるからである。注入されるのは
捕獲の規則だけであり(0007)、捕獲が守るのは粒度だけで種別の語彙は phase 1 に一切現れない
(0013)。文体の規則を一つ足せば、コードから奪う注意がその分増える。切った断面に主語が無いのは
分割の産物なので、切った側が補うのが素直でもある。

**`Splitting is a cut, not a rewrite` には例外を書く。**元の文が主語を省略できたのは隣の節と
主語を共有していたからで、切れば各片は自分の主語を要る。補完は復元であって書き直しではない。
ただしコーパスには捕獲の時点から主語の無い行(「Illustrator と同じ挙動」)も含まれ、そちらを
補うのは純粋な加筆になる。両方を `/pp-classify` の仕事として認める。

## 体言止めは `block-headings` の必要条件になる

当初は「文は断定系で終わること」を規則に足す案があった。**コーパスで検証して落とした** —
`しておく / と思われる / かもしれない / はずだ / だろう` は108行中0件で、この規則は何も
変えない。

一方、述語を持たない行は文ではなくラベルであり、コーパスで体言止めの行はすべて `tautology` か
`why` に落ちていた。

```
「同一パス /operator/templates/reorder の GET/PATCH 対」   [tautology]
「並び替えモーダル用の全件取得」                            [tautology]
「並び替え保存後に一覧を読み直すためのトリガ」              [tautology]
```

判定はこうなる。

```
各行に主語を補う
  ├ 補えた(述語がある)  → 通常の種別判定へ
  └ 補えない(体言止め)   → block-headings
```

**根拠は「ラベルは文ではない」だけである。**`block-headings` がどこへ行くかは参照しない。行き先
を種別の判別根拠にしないことは ADR 0027 が扱う。

## 因果の免除は動かさない

ADR 0013 の「因果(〜のため)は一件のまま」を変えない。因果を割ると原因と結果が別行になり、
`why` という種別が構造的に存在できなくなる。

```
「タイムアウトが多発したため非同期にした」
  → 「タイムアウトが多発した」  [external-facts]
  → 「非同期にした」            [tautology] → 破棄     ← why が蒸発する
```

型Dの3行はすべて文をまたいだ因果であり、「一行一文」を規則にすればこの3行を壊す。**文の数では
なく接続関係を見る。**従属節(〜ため / 〜ので)を作るものは一件、主節を並べるもの(逆接・並列・
句点)は二件である。主語の補完もこの線に沿う — 従属節の主語を補うことと、従属節を切り離すことは
別の操作である。

## Considered Options

- **「一行一文」を規則にする** — 最も機械的で判断が要らない。型Dの3行を壊す。因果が文をまたぐ
  ことは普通に起き、規則が文の切り方に依存する。
- **断定系を強制する** — 推測が種別を曖昧にするという想定に立っていた。コーパスで0件。規則を
  一つ足して何も変えないのは、注入と手順を重くするだけである。
- **主語の補完を捕獲側に置く** — 断面が生まれた場所で直せる。ADR 0007 と 0013 の線を越え、
  phase 1 の規則が文体にまで及ぶ。
- **推定無罪のまま、型Cだけを拾う規則を足す** — 差分は小さい。同一種別が二つ並ぶことを検出する
  規則は、結局「主張がいくつあるか」を数えることになり、推定有罪と同じ判断を別の名前で書く。

## Consequences

`/pp-classify` の split 件数は増える。ADR 0013 は「捕獲時の分割が雑になれば `/pp-classify` の
split 件数として現れる」と書いたが、以後その数は捕獲の質と分類の厳しさの両方を含む。二つを
分けて読むことはできなくなった。

`/pp-classify` は加筆をする最初の手順になった。復元と書き直しの境界は散文でしか守られておらず、
機構は無い。補った主語が原文に無かった意味を持ち込む失敗は、`all.csv` を読み返すまで見えない。

**この決定は ADR 0026 の前段にあたる。**行き先の移動だけを先に入れると、コードに残す価値のある
記述 — 触ると壊れる種類の why — が、割られないまま丸ごとログに落ちる。二つの決定の順序が制約に
なっている。
