# `.periplus/` は config.json も含めて全体を追跡しない

`.periplus/` は作業状態を置く場所であり、その中に一つだけコミット対象を混ぜると、
ディレクトリの意味が「作業状態」から「作業状態と設定が同居する場所」に変わる。
判断基準をチームで揃えたい場合は `config.json` を手で配る。ローカルのツール設定を
配るのと同じ扱いであり、そのために追跡対象を分岐させるほどの重みはない。

ADR 0002 が「チームやリポジトリによって妥当な線が異なる」と書いたことは、設定が
git を経由して配られなければならないことを意味しない。共有されないことによる実害
——同じリポジトリで criteria が黙って食い違う——は、config.json を置いている
リポジトリでのみ、かつ意図的に置いた人の周辺でのみ起きる。既定値をそのまま使う
限り全員が同じ規律で動く。

## Considered Options

- **config.json だけコミットし、pre.md と log.md を ignore する** — チームの線が
  レビュー可能になる。ただし `.periplus/` が「一時状態の場所」ではなくなり、
  periplus を状態と定義する CONTEXT.md と衝突する。ignore の記述も1行から2行に増え、
  規律が hook の外に漏れる。
- **設定を `.periplus/` の外に出す** — ディレクトリの意味は保たれるが、規律に関係
  するパスが2箇所に散る。

## Consequences

`log.md` も追跡されないため、引き金付きのエントリは各開発者のローカルに留まる。
チーム共有の負債キューとしては働かず、「ログが増えている」は個人の信号に留まる。
periplus が発火しているかどうかを外から知る手段は `.periplus/` の存在だけであり、
これは ADR 0010 で hook がセッション開始時に作ることで担保される。
