# v0.7.0 — 手順書から理由を落とし、誤読の余地を消す

## Issue

この版の設計をした対話で、モデルが `kind` と行き先を**二度**混同した。一度目は「四つの kind の
既定が同じ periplus だから、この区別は何も変えていない」と論じ、二度目は同じ論法で読む順の
4・5・6 を畳もうとした。ADR 0014 が語を二つに分けた理由そのものを踏み外している。どちらも
訂正したのはユーザーである。

同じ誤りが二度出るなら、それは誤読ではなく誘導である。誘導している箇所は特定できた。

- `skills/pp/SKILL.md:213-218` — 一つの表に二つの語彙が同居し、`code` が一行の中で二つの意味を
  持つ。左は「rows whose kind sent them to periplus」— kind が送ったという言い方 — で、右は
  `/pp-discuss` の `docs, code, or trash` である。`CONTEXT.md:153-155` は「別の語彙である」と
  明記しているが、**その断り書きは設計文書にあって、モデルが読むファイルには無い**
- `skills/pp/SKILL.md:226-247` — kind 表の百行下に、二セット目の行き先語彙が節として立つ
- `skills/pp-classify/SKILL.md:35-37` — `config.json` を読むなという規則が、その理由として
  `history` の行き先を書いている。規則が自分の禁止事項を実演している
- `skills/pp-discuss/SKILL.md:15-17` — 既定の routing を kind 名五つで焼き込んでいる。
  ADR 0029:180-182 が既に一度直しており、**同じ一文が二度ずれている**

四箇所とも `skills/pp/SKILL.md` が手順書と説明書を兼務していることから出ている。`/pp` の流れに
一度も現れない `docs` / `here` / `trash` の語彙が、`/pp-classify` が kind を決めている最中も
文脈に居座っていた。

**この版が削る目的はトークンではなく誤読の余地である。軽くなるのはその結果にすぎない。**
初稿は「token 消費の低減」と書いていたが、それは動機ではなく効果だった。

## 決めたこと

- **`skills/*/SKILL.md` は実行手順書、`README.md` が全体の説明書、ADR が個々の決定を持つ。**
  この役割分担は今まで宣言されていなかった
- **剪定規則は「その一文を消して、手順の実行結果が変わるか」。** 変わるなら手順の一部で残す。
  変わらないなら `doc-restatement` か `why` であり、ADR が既に持っている
- **手順書に理由は書かない。**「X せよ、なぜなら Y」は「ここでは Y が当たらない」という反論の
  足場を作る。裸の命令には足場が無い
- **`always` 区間も例外にしない。** 毎セッション注入され、`/pp-refactor` の四十七倍の頻度で
  読まれる。命令に勝たせるために弁明が要るという主張は立つが、足場を与えるほうが負ける
- **落とした行はどこにも積まない。** `log.csv` の行は `file:line` を持つコードについての記述で
  あり、SKILL.md の散文はその形をしていない。ツールの使い方ではない
- **`README.md` は範囲外。** 落とす内容は全部 ADR が持っており、ADR は「後から読み返せる場所」の
  試験(`CONTEXT.md:59-60`)を通る。既存の重複一行(`:128-129`)だけ減らす

ADR 0007:30-41 は 2026-07-30 に `always` 区間へ三段落を足しており、削除の条件を「三段落が発火率を
上げなかった場合」と書いている。**その比較はできない。**当時の作業ファイルは `.pre.md` で、
`all.csv` は CSV 化(44a17c4, 08-02)以降しか持たない。代わりの根拠として、0007 が足した三段落は
**三つとも命令部分が残る**ことを確かめた。落ちるのは付随する弁明だけである。

## 実装時の制約

`hooks/periplus-activate.test.js` が三つ持っている。

- `:302` — CSV 行形式は README と四つの SKILL.md の**全部**に必要。質問に上がった「重複」の一部は
  テストが要求している
- `:270` — `delivered × 3 < skill`。`pp/SKILL.md` を `always` 区間より速く削ると落ちる。実測
  `2693×3 < 13770`、この版の見積り `1868×3 < 9535` で通る
- `:230` — 表の下で 4・5・6 が分かれていること。順序表 `133-141` が満たすので、その下の弁明
  `143-159` は落とせる

`always` 区間の変更は一つのコミットに分ける。発火率を動かしうるのはそこだけで、残り四つは全て
phase 2、`/pp` を呼んだ後にしか読まれない。落ちたらそのコミットだけを戻す。

## 測ること

形式が変わったためで、CSV になった今は同じ形で数えられる。
