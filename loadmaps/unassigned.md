

## current-limits を細分化するか

don't が見えなくなる問題は `current-limits`(→ code)で拾えている。ここは解決済み。

残る疑問は、`current-limits` が性質の違う二つを一つの種別で抱えていること。

- **意図的にやらない** — 決定であり、後続の作業は無い
- **まだできない** — 欠落であり、`upgrade-triggers` と対になる

行き先はどちらも code なので、分けても配送は変わらない。優先度が低いのはそのため。
ただし読み手にとっては別物で、同じ文面からはどちらか判別できない。「リトライは実装
しない」が決定なのか未着手なのかは、コードを読んでも分からない。

分けるなら ADR 0004(意図的逸脱は種別ではなく分割規則)と ADR 0014(種別の集合は閉じる)の
両方に当たる。

## langageルールのカスタマイズ・捕獲の言語を、周囲のファイルの言語に合わせるか

現行の phase 1 は「考えていた言語のまま書け」で、行はその言語のまま行き先に着く。会話の
言語とファイルのコメントの言語が違えば、`/pp` 経路では毎回不一致が起きる(日本語の会話で
英語のコードベースを触れば、日本語のコメントが英語のファイルに入る)。規律はこれを
「報告すべき不一致であって、黙って訳す根拠にはならない」としている。

捕獲の時点でファイルの言語に合わせて書けば、不一致は最初から発生しない。現行が
そうしていない根拠は `skills/pp/SKILL.md` にあり、訳すのは原文を手元から離した後の
書き換えであり一度書かれれば二次情報だと判別できなくなる、というもの。ただし**捕獲の
時点なら原文はまだ頭の中にある**ため、この理屈がそこまで強く効くかは怪しい。

優先度は低い。読めれば実害は無く、英語で書かれること自体は問題にならない。ADR 0006 と
言語規則の両方に当たるため、動かすなら独立の版として切る。

## 文書の陳腐化の検出は periplus の仕事か

v0.6.0 の `doc-restatement` は、名指しした行が記述と同じことを述べていることを条件にした。文書が
古く、記述のほうが正しい場合はこれで弾かれる。**残るのは、記述と文書が一致していて両方が古い場合**
である。このとき `doc-restatement` は正しく発火し、記述は捨てられ、古い文書は無傷で残る。失われるのは
記述ではなく「文書が古い」という発見のほうである。

実例がある。ADR 0014 が「README は hook が criteria を差し込んで注入すると書いていたが、そうは
なっていなかった」と記録している。

これは規律の外だと考えている。ADR 0021 が「コードを直すことは notes pipeline の一部ではない」と
引いた線の、文書側の対応物にあたる。文書の陳腐化を検出する道具は要るが、それは pre-comment を濾す
道具ではない。

動かすなら ADR 0021 に当たる。

## 分岐を復元元の一本にするか

ADR 0029:41 は drop の四つが「復元元で組織されている」と書いている。同じ軸に全種別を載せると、
順序は三問になる。

```
1. どこから復元できるか   コード / git log / describe-it / 文書と行
     ただし外側の事実は、文書にあっても 2 へ(ADR 0029 の 1 > 3)
2. 復元元が無い。事実か、決定か
3. 決定なら、誰が決め何が記録しているか(ADR 0029 の表)
```

入口の無い種別は v0.7.6 が分岐で塞ぐ。残る論点は軸そのもので、当たるのは ADR 0029 の骨(順序)で
ある。v0.7.6 のフローで分布が偏るなら発動する。

この案なら、v0.7.6 が残した未決 —— 理由の形をしていない行の着き先 —— も同時に決まる。第一問が
「どこから復元できるか」なので、理由かどうかを問う場所が最後に来ない。

## 発火しない種別をどう疑うか

0 件は「その種別が壊れている」証拠にならない。**発火する機会があったのに発火しなかった**ときだけ
が証拠であり、機会があったかは母集団を見なければ言えない。`.periplus/all.csv` と `swept.csv` の
対象ファイルを見ると、テストファイルは一つも通していない。`test-intent` の 0 件はこれで説明が
つき、種別の性能とは関係が無い。

ADR 0029 が `doc-references` を故障と判定したのも件数ではなかった。0029:23-27 ——「唯一の 1 件
すら定義どおりではない」。出た 1 件を開いたら定義とずれていた、が根拠である。

いま残っているのは `block-headings` で、根拠は件数だけである。ADR 0026:47-51 が疑う条件を既に
書いており(「ブロックが小さければ `tautology` と区別がつかない」)、動かすならその条件か、他の
リポジトリの `swept.csv` が出てからである。
