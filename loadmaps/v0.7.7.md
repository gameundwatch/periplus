# v0.7.7 — 捕捉規則の二重払い（保留）

v0.7.6 で `/pp` が読む本文は 11,620 字になった。残っている最大の重複はここではなく、**hook の
注入と `/pp-capture` が同じ本文を持っていること**である。この版では決めない。試験を回したが、
決め手が出なかった。

## 何が重複しているか

`SessionStart` の注入と `skills/pp-capture/SKILL.md` を diff すると、差は先頭 7 行だけである。

```
< PERIPLUS ACTIVE — 7 in the log
<
< # Periplus — phase 1
<
< Comments do not go straight into the source. …
（以降 36 行、完全一致）
```

`/pp` が `/pp-capture` を呼ぶと、セッション開始時に既にコンテキストへ入っている 1,625 字を
もう一度読む。

`pp-capture` の中身は、退避の規則だけではない。

| 何を言っているか | 字 |
| --- | --- |
| 持続・発火条件・退避の規則・「ソースには書かない」 | 550 |
| 行形式とその細目 | 269 |
| 分割規則 | 355 |
| 終了条件（`/pp` を呼べ）と報告の文言 | 284 |

行形式は 5 ファイル(`pp-capture` / `pp-classify` / `pp-resolve` / `pp-refactor` / `README`)に
書かれており、捕獲だけの持ち物ではない。分割規則は `pp-classify` にも別の言葉で 218 字あり、
`/pp` の一回で両方読む。

## 検討した案

**一行注入（ポインタ）** — 注入を「規則は `skills/pp-capture/SKILL.md` にある、コードを書く前に
読め」の 308 字にする。コードを書かないセッションでは −1,526 字。書くセッションでは本文を後から
読むので横ばいか微増になる。得をするのは「開いただけのセッション」だけである。

**編集イベントで撃つ** — CLI 2.1.228 は `PreToolUse` / `PostToolUse` を持ち、`matcher` にツール名
を書けばファイル編集で発火する。だが**順序が合わない**。どちらもモデルが編集内容を組み立てた後に
発火するので、規則が先に無ければ効かない。ADR 0010 に追記した。編集イベントで撃てるのは規則では
なく合図（`pre.csv` の件数、`/pp` をまだ呼んでいないこと）に限られる。

## 試験

注入 2 変異 × AOJ の課題 2 問。副エージェントに注入文を前置きし、同じ課題を解かせた。

- A = 現行の注入 1,834 字
- B = ポインタ 308 字（規則はファイルを読めとだけ書く）

| | A | B |
| --- | --- | --- |
| AOJ 0015 / Ruby | 捕獲 3 — code 1 / drop 2 | 捕獲 3 — code 1 / periplus 1 / drop 1 |
| | 32,239 tok / 92 秒 | 33,696 tok / 97 秒 |
| AOJ 0021 / Python | 捕獲 3 — code 0 / periplus 2 / drop 1 | 捕獲 5 — code 1 / periplus 1 / drop 3 |
| | 30,164 tok / 78 秒 | 33,530 tok / 111 秒 |

4 回とも解答はサンプルと一致し、`pre.csv` は空、行形式も報告の文言も規則どおりだった。
**発火しなかった回はゼロ。**トークンは 4 回とも B のほうが多く、合計 +7.1%。注入で節約した
1,526 字より、`SKILL.md` を読む往復のほうが高い。

## なぜ決めないか

**n=2 で差が出ないことは、どちらの証拠にもならない。**「ポインタで足りる」とも「現行が過剰」とも
言えない。

ADR 0007 の追記(2026-07-30)が記録しているのは、注入を薄くしたときに規律が**そもそも発火しな
かった**ことである。90 秒で終わる課題は、その現象が出る条件ではない。

試験の設計にも穴がある。副エージェントは `/pp` skill を使える状態だった。hook の注入だけが頼りの
実環境より条件が良く、**B が「ポインタを読んで従った」のか「skill が使えたから従った」のかを
分離できていない。**

## 次に測るなら

- 長い課題（複数ファイル、数十分）— 発火が落ちるのは短い課題ではない
- `/pp` skill を使えない条件 — 注入だけで発火するかを見る
- 同じ課題の反復 — n=2 では分散が分からない

作業場は `periplus-injection-workspace/`(scratchpad)。**セッションを跨いで残らないので、上の表が
この試験の記録である。**
