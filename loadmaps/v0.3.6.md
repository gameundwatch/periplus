# v0.3.6 — `.log.md` はログであり、文書を書くための証拠である

## 概要

v0.3.5 で `unspecified-choices` を足したことで、ログに着く記述の性質が変わる。既定で
periplus に行く種別は二つから三つになり、そのうち新しい一つは未決着の設計判断である。

これが `.log.md` の現行の性格づけと衝突する。ADR 0003 は periplus を**状態**と定義し、
「置かれた記述は必ず出ていく」とした。その帰結として「空に近いことが正常、溜まっている
ことが異常」があり、閾値警告・ステータスラインの琥珀色・`/pp-discuss` の勧誘は、すべて
その上に立っている。

**この読みを捨てる。`.log.md` はログである。**文書にエスカレーションされない記述は残る
べくして残る。滞在は在庫ではなく、**いずれ文書を書くときの客観的証拠**の蓄積である。

出口を要求しない理由は連鎖である。`here` に行き先を決めさせると、次はその行き先の
ファイルを議論するコマンドが要り、その先も要る。終わらない。

periplus はまずコメントの描きすぎを防ぐ道具であり、その次に設計と実装の Gap を探す意図
を持つ。`.log.md` はその Gap の記録であって、処理待ちの列ではない。

同じ版で `updated` カラムを削除する。実運用で予想以上に頻繁に切り替わり、区別の器として
機能していない — が、より強い理由は上の決定から来る。ログがキューであることをやめた以上、
`updated` が担っていた「議論済みか未読か」の区別そのものが要らない。

## 決定

### 1. `.log.md` の性格づけを書き直す。0003 には触らない

**ADR 0003 は編集しない。**慣行はリポジトリに既にある — ADR 0020 がログの出口を三つから
四つへ置き換えたとき、0003 の「pick・昇格・破棄」はそのまま放置された(`0003:7`)。0022 も
0014 に対して同じ書き方をしている。新しい ADR が何を上書きするかを自分の中で述べ、古い
ADR は読まない。レガシーとなった ADR を読ませないことが、この慣行の目的である。

0023 が撤回するもの:

- Decision の「**一時的**に居る場所」「いずれかで**必ず出ていく**」
- Consequences の「空に近いことが正常/溜まっていることが異常」「棚卸しの中心的な仕事は
  出口の見えないエントリを警告すること」

**MECE の核は残る。**必要なのは「periplus と恒久層に**同時に**存在しない」ことだけで、
「いつか出ていく」ことではない。定義軸は「未処理という状態」から「決着の有無」へ移る。

### 2. `here` を許容する

**`here` と `docs` の境界は「決着したか」で引く。**

- **ログ** — 議論中・未決着の記述
- **docs** — 決着した決定

`docs` の三条件(hard to reverse / surprising without context / real trade-off)は「決着の
試験」としてそのまま生きる。決着していないものが通らないのは、失敗ではなく正しい挙動に
なる。`unspecified-choices` は定義上まだ決着していないので、最初は `here` に居るのが正しい。

`/pp-discuss` の二段落は性質が違うので別々に始末する。

| 箇所 | 何を |
| --- | --- |
| `skills/pp-discuss/SKILL.md:116-118` | 「警戒すべき失敗モード」「ログは意図されなかった保管庫に静かになる」→ 削除 |
| `skills/pp-discuss/SKILL.md:119-122` | 再発の対抗圧 → Ending(`:157-159`)に寄せ、重複を畳む |

寄せる際に根拠を張り替える。再発は故障への対抗圧ではなく、**Gap が本物であることの検出**
である。提案する内容も「文書を作れ」ではない — ログは文書を作るための客観的証拠であり、
同じ主題が二件揃ったことがその証拠になる、と言う。

**序列の比喩を捨てる。**`docs` が主要な道で他の三つは路肩、という言い方(`pp-discuss:15-17`、
`pp/SKILL.md:186-194`、`CONTEXT.md`)をやめる。`docs` はエスカレーションの行き先であり、
そこへ出ることがログの目的だが、出られないことは失敗ではない。四つの行き先は序列ではなく、
決着の有無で分かれる。

同じ箇所の事実誤り — 「既定でここに来るのは二種別だけ」は、0022 以降**三種別**である。

### 3. 出口の要求を撤回する

`skills/pp-discuss/SKILL.md:133-150` の「Entries with no trigger」を**節ごと削除する。
代わりは立てない。**この節は 0023 が撤回する「必ず出ていく」を執行するためだけに存在する。

同じ根拠で消えるもの:

| 箇所 | 何を |
| --- | --- |
| `skills/pp/SKILL.md:196-199` | 「空に近いログが働いている証拠」「出ていく条件を名指ししないエントリは恒久在庫」 |
| `CONTEXT.md` の `## 引き金` | 節ごと削除 |

用語集からも語を落とす理由は、どのコマンドも参照しない語を残すと次に読む人がそれを執行
しようとするからである。`## 現在の限界` にある「見直し条件」は別語(種別
`upgrade-triggers`)なので残る。

### 4. 閾値警告と `warnThreshold` を削除する

`here` を広く許容すればログは正当に伸びる。既定閾値は 10 なので、毎セッション警告が出続け、
警告は風景になって死ぬ。

**ステータスラインの色を変える機能は要らない。**`[PERIPLUS:N!M]` の数値は `.log.md` と
`.pre.md` の行数にすぎない。`hooks/periplus-statusline.js` の `WARN` 定数と `tag()` の
`warnThreshold` 引数が落ち、タグは常に海色になる。

`config.json` に残るキーは `criteria` だけになる。v0.4.0 が自動生成する config もそれに従う。

### 5. SessionStart ヘッダを削る

`buildContext()`(`hooks/periplus-activate.js:226-252`)が積む三つを個別に決める。

**件数は残す。**語だけ変える — `${count} entries pending` → `${count} in the log`。残す理由は
ステータスラインを入れない利用者に件数を見せる手段が他に無いことで、`pending` を捨てる理由は
滞在が正常になった以上その語が嘘になることである。閾値の枝に付いていた `/pp-discuss` の勧誘は
一緒に消え、**復活させない**。

**config 通知の一行(`:239-242`)を落とす。**phase 1 に注入されるのは capture rule だけで、
そこに destination は出てこない(ADR 0007)。表が要るのは `/pp-resolve` であり、`criteria`
サブコマンドで自分で引く。読み手の居ないトークンである。

**`.pre.md` の未配達警告(`:234-236`)は残すが、SessionStart 限定にする。**これは本当に故障
を指しており(その作業はコメント無しで出荷された)、`.pre.md` が空なら一文字も出ない。
SubagentStart から外す理由はトークンではなく宛先違いで、subagent は親が捕まえた行を書いて
いないのに「新しいコードを書く前に `/pp` を走らせろ」と読み、ユーザーが合意していない
drain を親の `.pre.md` に対して行う。枝分けの前例は statusline の勧誘(`:294`)。

これにより `main()` は `loadConfig` を呼ばなくなり、`loadConfig` の生き残る用途は `criteria`
サブコマンドの表だけになる。

### 6. `updated` カラムを削除する

行の書式は次になる。

```
- <created> `<file>:<line>` [<kind>] <the note>
```

書式の行は 7 箇所にある — `pp/SKILL.md:45`(hook が注入する capture rule 本体)と `:169`、
`pp-classify/SKILL.md:23` と `:64`(例)、`pp-resolve/SKILL.md:39`、`pp-refactor/SKILL.md:53`、
`pp-discuss/SKILL.md:69`(例)、`README.md:80`。

同時に死ぬもの:

| 箇所 | 何を言っているか |
| --- | --- |
| `pp-discuss/SKILL.md:56-58` | 一度議論された entry の議論を蒸し返すな |
| `pp-discuss/SKILL.md:146-150` | created と updated の差が、未読の entry と議論して生き残った entry を区別する唯一の手段 |
| `pp-discuss/SKILL.md:114, :131` | `here` に送ったとき updated を now にする |
| `pp-discuss/SKILL.md:44-47` | 「created の古い順、updated 順では決して並べるな」の後半が空文になる |
| `README.md:86-90` | 「二つ目のタイムスタンプは何かが起きるたびに動く」 |

上の二つはどちらも**代わりを立てずに削る**。§3 で節ごと落ちるものに含まれ、証拠には
「議論済みか」の区別が要らない。同じエントリに再び行き当たることこそが、§2 で残すと決めた
再発シグナルそのものである。

**移行措置は立てない。**`ROW_RE`(`hooks/periplus-activate.js:29`)は新書式のみを読み、旧行は
数えない。`.periplus/` は untracked で、既に使っているマシンは少ない。

archive は `ROW_RE` の問題ですらない — `rows()`(`:106`)が呼ばれるのは `.log.md` と `.pre.md`
だけで(`countEntries` / `countPending` / `countUnclassified` が全用途)、二つの archive は
コードから一度も読まれない。新旧が混ざったまま置かれ、0015 / 0018 の「編集されず、決して
drain されない」とも衝突しない。

## 書き起こす ADR

**0023 一本。**`updated` の削除を独立させない理由は §6 の通りで、切り替わりの頻度ではなく
ログがキューであることをやめたことが理由になったため、同じ決定の帰結になった。

```
0023 — .log.md は文書を書くための証拠であり、出口を要求しない

Decision
  ログはログである。エスカレーションされない記述は残るべくして残る。
  滞在は在庫ではなく、いずれ文書を書くときの客観的証拠の蓄積である。
  periplus を分けるのは処理の進捗ではなく決着の有無。

  出口を要求しない理由 — here の行き先を決めさせると、その行き先を議論する
  コマンドが要り、連鎖は終わらない。

  0003 が撤回されるもの — Decision の「一時的」「必ず出ていく」、
  Consequences 全体。MECE の核は残る(必要なのは同時に存在しないことだけ)。

節として収まるもの
  - here / docs の境界は決着の有無で引く。docs の三条件は決着の試験として生きる
  - 序列(docs = 主要な道、他 = 路肩)を捨てる
  - 閾値警告と warnThreshold の廃止(0003 の Consequences が唯一の根拠だった)
  - 出口の要求の撤回(「Entries with no trigger」と用語「引き金」の削除)
  - updated カラムの削除(証拠に議論済みの印は要らない)
```

**0015 は触らない。**ただし 0015:33 は archive をログに混ぜない理由として「溜まっている
ことが異常のシグナルでなくなり、閾値警告が意味を失う」を挙げており、0023 がその閾値を自分で
消す。0015 の決定自体は別の理由(`.all.md` は測定の器 — 0022:45-48)で立つので、0023 の中に
「0015 の理由の一つは消えるが、決定は別の理由で残る」と一文書く。
