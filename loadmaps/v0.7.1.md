# v0.7.1 — 手順を、それを使う者のファイルに置く

## Issue

v0.7.0 は手順書から理由を落とした(ADR 0031)。落とし切った後も脂肪が残る。残っているのは
文言ではなく**置き場所**である。

### `always` 区間が `/pp` の文脈に二度入る

hook がセッション開始時に `alwaysSection()` を注入し、その後 `/pp` が `skills/pp/SKILL.md` を
丸ごと読む。**phase 1 の捕捉規則が二度入る。**`/pp` は phase 2 であって、捕捉はしない。

実測 2,535 字(48 行)、v0.7.0 後の見積りで約 1,700 字。`/pp` を呼ぶたびに払っている。

ADR 0007 は「文言は SKILL.md から切り出しているため、常時の規則と `/pp` の本文が別々の規律に
分かれることはない」と書いた。これは**一箇所しか無ければ、より強く保たれる**。

### 分類器の道具が、分類器の外に置いてある

kind 表(31 行)と読む順・判定材料(60 行)は `/pp-classify` の道具である。しかし
`skills/pp-classify/SKILL.md:30` は「表は `skills/pp/SKILL.md` にある」と外を指しており、
**単独で呼ばれるたびに 14,705 字のファイルを開かせている。**`/pp-refactor` も同じ経路を通る
(`skills/pp-refactor/SKILL.md:21-23`)。

**これは `/pp` には一切効かない。**三ファイルとも読むので、移しても総量は変わらない。効くのは
単独経路だけである。

### 四ファイル表は参照であって手順ではない

`skills/pp/SKILL.md:213-224`。ADR 0031 が README を説明書と決めた以上、ここは README が持つ。

## 決めたこと

- **`always` 区間を独立ファイルに出し、hook がそれを読む。**`skills/pp/SKILL.md` からは消える
- **kind 表・読む順・判定材料を `skills/pp-classify/SKILL.md` へ移す。**使う者が持つ
- **四ファイル表を `README.md` へ移す**
- **`/pp` は skill として残す。** 三つ全部やると `skills/pp/SKILL.md` は約 30 行になり、中身は
  「`/pp-classify` を走らせ、次に `/pp-resolve` を走らせろ。行形式はこれ。言語は変えるな」だけに
  なる。それでも `always` 区間が `invoke /pp` を指している以上、呼べる名前が要る。ADR 0016 は
  classify と resolve を分けたが `/pp` を消してはいない
- **v0.7.0 とは版を分ける。** 軸が違う — 0031 は「理由は手順書に置かない」、この版は「手順は
  使う者が持つ」。加えて 0031 は発火率で戻す条件を置いており、その観測期間に hook とテストの
  構造変更が混ざると、`all.csv` の件数が何のせいで動いたのか読めなくなる

## 呼び出し経路ごとの見積り

v0.7.0 が入る前の実測と、v0.7.0 後・この版後の見積り。

| 経路 | 現在 | v0.7.0 後 | この版後 |
| --- | --- | --- | --- |
| `/pp` | 26,283 字 | 19,390 | 16,990 |
| `/pp-classify` 単独 | 22,021 | 16,160 | **9,360**（−58%） |
| `/pp-refactor` | 32,189 | 23,580 | **16,780**（−48%） |
| `/pp-discuss` | 7,103 | 4,820 | 4,820 |
| `/pp-resolve` 単独 | 4,262 | 3,230 | 3,230 |

`/pp` が得るのは `always` の抽出と四ファイル表の移動だけで、約 2,400 字。kind 表の移動は
`skills/pp/SKILL.md` から `skills/pp-classify/SKILL.md` へ移るだけで、`/pp` の総量は変わらない。
**得をするのは `/pp-refactor` と `/pp-classify` 単独である。**

## 変えるもの

- `skills/pp/SKILL.md` — 約 30 行になる
- `skills/pp-classify/SKILL.md` — kind 表・読む順・判定材料を受け取る
- `skills/pp-refactor/SKILL.md` — `:21-23` の参照先
- `README.md` — 四ファイル表
- `hooks/periplus-activate.js` — `SKILL_PATH`(`:33`) が二つに割れる。`always` を読む先と、
  kind 表を読む先が別のファイルになる
- `hooks/periplus-activate.test.js` — 三本

## 実装時の制約

- `:259-260` `the injected capture rule is lifted verbatim from the skill` — `always` が
  `skills/pp/SKILL.md` に含まれることを検査している。**この版はその前提を壊す。**書き換え先は
  「hook が読む先と、注入される文言が一致すること」であり、検査の目的(drift 防止)は変わらない
- `:270` `delivered × 3 < readDiscipline()` — 注入が skill の一部であることを比率で担保して
  いる。`always` が skill の外に出ると比較が意味を失う。**この版で消える**
- `:197` `:358` — kind 表を `readDiscipline()` から読んでいる。参照先の変更が要る
- `:302` — CSV 行形式は README と四つの SKILL.md の全部に必要。約 30 行になる
  `skills/pp/SKILL.md` も、行形式は持ち続ける
