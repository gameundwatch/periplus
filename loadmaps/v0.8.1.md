# v0.8.1 — 濾すのはタスクではなく、書き終えた一つの変更ごと

捕獲はコードを書いている間ずっと効き、濾過はタスク完了時に一度だけ走る。細かくコミットを刻む作業
形態を取ると、実装が先にコミットへ入り、コメントは最後にまとめて入る。

```
いま:
  実装 ─commit A─▶ 実装 ─commit B─▶ 実装 ─commit C─▶ /pp ─commit D
  捕捉  …………………………………………………………………………………………▲ ここで初めてソースに入る
                                                     D の中身はコメントだけ

これから:
  実装 ─/pp─▶commit A ─ 実装 ─/pp─▶commit B ─ 実装 ─/pp─▶commit C
        ▲ 書き終えた変更ごとに濾す
```

**コメントだけのコミットは症状である。**軸は、実装とその説明が別の差分に割れることにある。差分の
把握が困難になる。

原因は単位が書かれていないことである。ADR 0006 は「コード本体が完成した時点で一度だけ」と決めたが
**完成の単位を定義しておらず**、`hooks/capture.md` も `any piece of work` と書くだけで、暗黙に
「タスク全体」と読まれていた。

## 決めたこと

決定と却下案は [ADR 0038](../docs/adr/0038-the-unit-of-completion-is-one-finished-change.md) が持つ。

**A. 単位は、いま書き終えた一つの変更。**git では commit に一致するが、**規律には `commit` と
書かない** — periplus を git に縛らない。

**B. 門は置き換える。**タスク完了の門は消える。文書が背後にある作業にだけ発火する(ADR 0037)以上、
コミットされずに終わったのに `pre.csv` に行が残る状態はバグであって、二つ目の門を持つ根拠にならない。

**C. 単位を否定形で名指しする。**`not the task it belongs to` の一節だけが既定の読みを殺す。

**D. 完了報告も変更ごと。**門と報告の単位が食い違えば、申告(ADR 0012)が証拠として機能しない。

**E. `/pp` の description も揃える。**常時視界に載る `at the end of any coding task` が残れば、
注入された C と正面から食い違う。

## 変えるもの

## この版で触らないもの

**コード。**変わるのは注入される散文と frontmatter の一行だけである。

**ADR 0006 の決定本体。**「実装中は退避だけ、完成後に分類」は動かない。0038 が足すのは、0006 が
書かなかった単位である。「一度だけ」は「完成ごとに一度」と読む。

**`CONTEXT.md`。**足すのは*作業*の語で、あそこは*記述*の語彙である。単位の語は既に 0006 にあり、
欠けていたのは定義だけだった。

**テスト。**ADR 0036。既存テストは `capture.md` の先頭行と行形式しか見ておらず、どちらも動かない。
確認手段は報告の文言である — 一つのタスクで `periplus: N filtered` が複数回出れば単位は動いており、
最後に一度だけなら動いていない。

**固定費。**注入は 12 語増える。プロンプト全体を図に移す版が控えているので、この版では許容する
(→ [v0.9.0](v0.9.0.md))。

**v0.9.0 の棚卸し表。**同じファイルの同じ範囲を触るため行番号が古くなるが、更新は後追いでよい。
v0.9.0 は自ら「まだ決まっていない」と宣言する下書きであり、決着済みの修正を人質に取らせない。
