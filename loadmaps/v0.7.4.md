# v0.7.4 — `/pp` を呼ぶだけにし、二重にある文を落とす

## 実測

固定費(毎セッション、コードを書かなくても払う)は ponytail の 1/2.8 で、既に軽い。

| | periplus | ponytail |
| --- | --- | --- |
| SessionStart 注入 | **1,834** 字 | 5,322 |
| description 合計 | **1,092** | 2,743 |
| 計 | **2,926** | 8,065 |

差はタスク毎に出る。ponytail は姿勢なので注入文が製品の全部で、実行費用がゼロ。periplus は
`/pp` を呼ぶたびに本文四つを読む。

| `/pp` が読む本文 | 字 |
| --- | --- |
| `pp` | 1,970 |
| `pp-capture` | 1,773 |
| `pp-classify` | 7,876 |
| `pp-resolve` | 2,415 |
| 計 | **14,034** |

一回で ponytail の注入 2.6 個分。ADR 0007 が同じ比率を既に実測している —「注入本文は差分の
23%でしかなく、残りは退避と振り分けの作業そのもの」。この版が削るのは文言側だけで、作業側は
別の版に置く。

## 決めたこと

**A. `/pp` は三つを順に呼ぶだけにする。** `/pp-capture` → `/pp-classify` → `/pp-resolve`。
何をどう処理するかは呼び先のファイルが持ち、`/pp` は持たない。ADR 0032 が置き場所の規則を
既に書いており、0033 が `/pp` を三コマンドの合成に戻した後も、`/pp` 側に処理の記述が残って
いた。責務が分かれていない。

**F. 二重にある文は一箇所に寄せる。** A の中身はこの二つである。

- 言語規則(`pp:32-39`, 420 字)— `pp-resolve:44-48` がほぼ同文を持つ。配送の規則なので
  `pp-resolve` に残す。分割時の言語は `pp-classify:143` が別に持っており、そのまま
- 行形式と四ファイルの関係(`pp:41-50`, 312 字)— `README.md:81-103` が同じ表を持つ。
  ADR 0032 が「四ファイル表は README のものだけにする」と既に決めている

**B. `/pp-classify` から重複した規則と余分な例を落とす。** `/pp` が読む本文の 56% を占める。

- 「Give every row a subject」(501 字)と「Split unless there is a reason not to」(1,041)が
  同じ分割規則を図と例で二度述べている
- Output 節(637 字)が一つの出力形式に例を五つ並べている

kind 表(1,466 字)は分類器の道具なので残す。ADR 0032 が `pp-classify` に置いた当のものである。

**E. 通しで走るとき `/pp-classify` は報告しない。** `/pp` の中では classify の一行/行が
resolve の一行/行にほぼ含まれ、同じ行をユーザーが二度読む。単独呼び出しの報告は変えない —
ADR 0016 が作った「配送される前に反対できる場所」は `/pp-classify` を単独で呼んで止めた
ときに立つのであって、通しで走る `/pp` の途中には立たない。

## 変えたもの

- `skills/pp/SKILL.md` — A, F
- `skills/pp-classify/SKILL.md` — B, E
- `.claude-plugin/plugin.json` — 版

## この版で触らないもの

**捕捉規則の二重払い。** hook の注入本文と `skills/pp-capture/SKILL.md` の本文は、見出しを
除いて一致する(`diff` 実測)。`/pp` はセッションに既にある 1,773 字を読み直している。ADR
0032 が一度潰し、0033 が skill 化で戻した費用である。`/pp` が三つ全部を呼ぶことは 0033 の
決定なので、切るなら hook 側か呼び出し条件の軸で、別の版に置く。

**作業側の費用** — `/pp-classify` の文書検索に上限がないこと、`/pp-resolve` の行単位 drain。
挙動が変わるので、文言を削るこの版とは分ける。
