# v0.3.3 — `/pp-discussion` を `/pp-discuss` に改名する

## 概要

コマンド名は動詞で名乗る、という原則を既存のコマンドに適用する。`discussion` だけが
名詞であり、`pp`・`classify`・`resolve`・`refactor` は動詞である。

名詞の名前は、それが状態を指すのか操作を指すのかを読み手に決めさせる。`/pp-resolve` が
「解決する」と読めるのに対し、`/pp-discussion` は「議論」という物を指しているように読め、
何が起きるのかが名前から確定しない。

また、`/pp-discuss`で何をするかという点も考慮したい。
現時点ではcodeへの埋め込みか.log.mdへの保留か、消去かを議論で決めるが、
個人的にはadrをはじめとするdocsへのエスカレーションをメインとしたい。
そのためto(exit)の分類は大分類でこうなる

`here` -> .log.mdから移動しない。保留
`code` -> コード本文にコメントとして移設。
`docs` -> コメント該当が示す内容を設計時の文書やADRにエスカレーションし、後続の開発に反映させる
`trash` -> 当該内容を削除。

原則そのものは `CONTEXT.md` の「コマンド名」に置いてある。

## なぜ単独のリリースなのか

利用者が打つコマンド名の破壊的変更であり、他の変更に混ぜると、大きな変更の中に紛れて
気づかれないまま既存の呼び出しが壊れる。差分としては小さく、単独で切れる。

## 変更するファイル

v0.3.2 で `/pp-list` を削除した後の参照。

- `skills/pp-discussion/` → `skills/pp-discuss/`、frontmatter の `name` を含む
- `skills/pp/SKILL.md` — periplus 行き先の説明、`no-trigger` の言及、コマンド一覧
- `skills/pp-resolve/SKILL.md` — 引き金の無い行への警告
- `hooks/periplus-activate.js` — 閾値超過時に案内している `/pp-discussion`
- `README.md`
- `.claude-plugin/plugin.json` — バージョン

書き換えない: `docs/adr/*`、`loadmaps/v0.3.0.md`・`v0.3.1.md`・`v0.3.2.md`。過去の記録。

## 決めていないこと

`discuss` は原則を半分しか満たしていない。`list`・`classify`・`resolve` が**結果**を名乗る
動詞であるのに対し、`discuss` は**過程**を名乗る動詞で、何が起きるか(ログが減る)は名前から
出てこない。効果で名乗るなら `/pp-drain` にあたる。

一件ずつ合意を取る性質は `discuss` の方が伝わるため、現時点では `discuss` を採る。原則を
適用するリリースで原則を半分しか満たさない名前を選んでいることは、ここに記録しておく。

旧名を一リリースだけ別名として残すかどうか。
-> 残さない。Claude Code のスキルに alias 機構は無く、残すにはディレクトリを丸ごと重複
   させるしかない。
